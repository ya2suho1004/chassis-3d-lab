## 2. 시험 상태 (설계 15 §8의 D01~D12)

상태 뜻: **LOCAL-PASS** = 로컬 모의(Node 시트·잠금 모의 또는 개발 서버 가짜 수신점)에서 통과. **NOT_RUN** = 실제 Google 배포·학교 기기·학교망에서 아직 실행 안 함. 설계 15의 통과 조건은 실제 환경 증거이므로, LOCAL-PASS는 "코드가 계약대로 동작함"의 증거일 뿐 직접 경로 채택의 증거가 아니다.

## 2-1. Codex 읽기 검토(2026-10-26) 반영

B1 `__proto__` 우회 차단, B2 스냅샷 문맥 전부 대조(`DemoSnapshots.gs`), B3 의미 검증, B4 설정 fail-closed, B5 정본 행 재검증, B8 record 1.0.0 지원을 반영(`tests/appsScriptHardening.test.ts`). B6: `setNumberFormat('@')`는 날짜 변환 방지의 보장이 아니므로 실배포 D01에서 acceptedAt·payloadJson이 문자열 그대로 돌아오는지 확인한다(재읽기 비교가 다르면 ack가 나가지 않음). B7: `RATE_LIMITED`는 누적 상한이라 자동 회복이 없고 교사 설정 변경이 필요하다. 모의의 한계(실제 ScriptLock·Sheets 변환·CORS)는 그대로 NOT_RUN.

## 2-2. Codex 2차 검토(회신 B) 반영

남은 P2를 닫았다: B3-a 시간 검사는 `timeQuality=uncertain`이면 벽시계 비교 생략, B3-b NPC 검사는 이벤트 한도에서 횟수·사건을 함께 올리지 않음(`recorded=false`, 화면 안내), B3-c `judgmentCorrect` 등식·등록 단계·off 하위 행동 순서 검사, B4 `ACCEPT_UNTIL`은 실제 달력 UTC만, B5 저장 `acceptedAt`도 같은 검사, 스냅샷 원장 append-only(`retired`는 회수만), 시험 코드 범위 `D-xx`. 테스트 204. Codex 판정(2026-10-26): 기존 P1 닫힘, 시험 배포 전 코드 차단 요인 없음(배포 승인 아님). 실제 Sheets·ScriptLock·CORS·학교망은 여전히 NOT_RUN.

## 2-3. Codex 3차 검토(회신 C) 반영

C-P2-1 복원 시 벽시계가 저장 시각보다 이르면 `timeQuality=uncertain`, 완료가 시작보다 이른 기록도 uncertain(원본 시각 보존). C-P2-2 수신점이 과제 버전별 선행 그래프(`stepPrerequisites`)와 parent 중복을 검사(중단 기록의 부분 이력은 허용). C-P2-3 record 날짜는 실제 달력 유효성 검사(오프셋·소문자·소수 허용, 2000-02-31 거절). C-P2-4·5 원장 병합은 중복 ID·예약 ID·같은 ID의 내용/검증 범위 변경을 실패시킴(`scripts/snapshotLib.mjs`). 힌트도 NPC와 같은 기록 한도 안내. 215 tests. Codex가 쓴 학교 점검표: `docs/design/docs/18_0C_DEPLOYMENT_CHECKLIST.md`.

## 2-4. Codex 4차 검토(회신 D) 반영

옛 초안(저장 시각 없음)은 복원 시 uncertain으로 보수 처리. off 하위 행동은 parent의 선행(read)을 첫 하위 행동에 상속하고, parent off는 exitVehicle 직후 사건이어야 함(fixture는 소급 제외). record 날짜는 RFC 3339 범위로 파싱(윤초는 UTC 23:59에서만, ajv-formats와 동일; 탭·축약 오프셋은 설치 Ajv의 확장이라 미지원). 원장 병합은 예약 ID를 원장 전체에서 검사하고 검증 범위 필드를 각각 독립 비교하며, 누락 필드 보강은 `SNAPSHOT_SCOPE_UPGRADE_REASON` 명시 이관으로만 허용해 `migrations`에 기록(이미 수행된 stepPrerequisites 보강은 소급 기록). 221 tests. Codex 상태 요약: `docs/design/docs/19_STATUS_2026-10-27.md`.

## 2-5. Codex 5차 검토(회신 E) 반영

윤초(:60)와 직후 일반 초의 순서가 뒤집히지 않도록 날짜 비교 키를 바꿈(윤초는 59.999와 다음 00:00:00.000 사이, 0~99년 보정 회피, 소수 반올림 없음). 이관 사유는 비어 있지 않은 문자열만(라이브러리·생성기 둘 다). 중복 선언 정리. 225 tests. Codex 판정(회신 E): 남은 P1 없음.

## 2-6. Codex 6차 검토(회신 F) 반영

시각 처리를 둘로 분리했다. **순서 비교**는 원문을 분해한 값(분 시작 → 초 → 윤초 여부 → 원문 소수부)을 사전식으로 비교해 어떤 소수 자릿수에서도 윤초(:60)가 59.xxx 뒤, 다음 00:00:00.000 앞에 온다. **경과시간 상한**은 순진한 epoch 차이에 UTC 자정 횡단 횟수만큼 1초를 더한다(윤초는 UTC 23:59:60에만 들어갈 수 있으므로). 비교 키를 경과시간으로 재사용하지 않는다. Codex 표본(2.6초/duration 3, 60.100→00:00:00.800/duration 2, 59.9999→60.000 순·역순)으로 고정. 230 tests.

## 2-7. Codex 7차 검토(회신 G) 반영

경과시간 상한: 시작·종료가 윤초(:60) 안이면 그 윤초를 정확히 세고(59.200→60.800 = 1.6초, 60.100→00:00:00.800 = 1.7초, 같은 윤초 안 0.5초), 끝점으로 알 수 없는 UTC 자정 횡단에만 1초 여유. 순서 비교의 소수부는 원문 숫자열(우측 0 제거 후 사전식)로 비교해 Number 정밀도와 무관(.9000000000000004 > .9000000000000003, .1 = .100). 234 tests. 윤초표가 없으므로 평범한 자정에도 1초가 붙는 보수적 상한임을 유지.

## 2-8. Codex 8차 검토(회신 H) 반영

경과시간 상한의 날짜·윤초 분기를 정수 ms(분 시작 + 초)로만 판정하고 소수부는 마지막에 작은 수끼리 더해, 자정 직전 7자리 이상 소수부가 epoch 덧셈 반올림으로 자정 횟수를 지우던 문제를 닫음(59.9999999→00:00:00.800 = 1.8000001, duration 2 수락). 236 tests. 방침: 이 P2가 닫히고 Codex가 종결을 확인하면 0C 후속 코드 변경은 docs/18·D01의 실제 관측에 근거해서만.

## 3. 실배포 시험 순서 (교사 작업, 학교 계정 정책 확인 뒤)

1. `server/apps-script/README.md` 1~4: 시험 Sheet·Apps Script·스크립트 속성·웹 앱 배포(모든 사용자·익명) → `/exec` URL.
2. `.env.production`에 URL → `npm run build` → GitHub Pages 배포(비공개 저장소의 Pages는 요금제 제한이 있을 수 있음. 막히면 저장소를 공개로 바꿀지 결정: 사진·개인정보는 저장소에 없음).
3. **D01 먼저**: 학교 태블릿(로그인 안 한 새 프로필)에서 시연 1건 → 교사 PIN → ‘대기 기록 지금 전송’ → ‘서버 접수 확인됨’ + 시트 1행 + 개발자 도구 Network에서 OPTIONS 없음·최종 응답 JSON 확인. 증거 양식: 설계 15 §8 끝(시험 ID / PASS·FAIL / 시각 / fixture 버전 / 앱·Script 버전 / origin / 기기·OS·브라우저 / 망 / ack 검증 / 행수 / receipt·acceptedAt·H / 오류).
4. D01 통과 시 D02·D07(HTML 응답은 실배포에서 재현 불가 → 단위 시험 증거로 대체)·D05(교사 정한 동시량)·D10·D11 순서. **D01이 실패(로그인 HTML·CORS·opaque)하면 부하 시험을 늘리지 않고 증거를 정리해 중계 전환(설계 15 §9)을 검토**한다.

## 3-1. 로컬 미리보기로 하는 D01 (2026-10-27 사용자 결정: 호스팅 결정 전 먼저 시험)

실제 HTTPS 출처(GitHub Pages) 대신 같은 컴퓨터의 운영 빌드 미리보기에서 실제 Apps Script `/exec`로 보낸다. 설계 15 §6의 "실제 Pages 출처에서 응답 읽기" 항목은 이 방식으로는 확인되지 않으므로 증거에 origin을 `http://127.0.0.1:4174`로 적고 D10은 NOT_RUN으로 둔다. 개인 구글 계정으로 시험 배포한다(사용자 결정 2026-10-27; 설계 15 §9의 학교 계정 전제와 다름을 기록).

1. Apps Script: `server/apps-script/README.md` 1~4 → `/exec` URL.
2. 프로젝트 루트에 `.env.production` 작성: `VITE_SUBMIT_ENDPOINT=https://script.google.com/macros/s/…/exec` (`.env.production.example` 복사).
3. 빌드·미리보기:

```bash
npm run build && npx vite preview --port 4174 --strictPort --host 127.0.0.1
```

   (앱 안에서는 `.claude/launch.json`의 `chassis-preview`.) 브라우저에서 http://127.0.0.1:4174/ 열기. 시작 화면 배너에 "(개발용 가짜 수신점)" 표시가 없어야 한다.
4. D-01 코드로 시연 1건 → 결과 화면 → 다음 학생 → 하단 ‘대기 기록 지금 전송’(PIN 0000) → ‘서버 접수 확인됨’과 접수번호. 시험 Sheet `canonical` 탭에 1행(5열) 확인, 접수번호·acceptedAt·payloadHash가 화면 JSON과 같은지 대조.
5. 같은 기록을 ‘강제 재전송’ → ‘서버 접수 확인됨’(duplicate) 그대로, 행 수 변화 없음(D02 축소판).
6. 개발자 도구 Network: POST가 `text/plain;charset=UTF-8`, OPTIONS 없음, 최종 응답 JSON. 증거를 `docs/design/docs/18` 양식으로 기록(이메일·토큰·일회성 URL 제외).

## 3-2. GitHub Pages 배포 (2026-10-27 사용자 결정: 저장소 공개 전환)

- 저장소를 공개로 전환(사진·개인정보·시트 ID·배포 설정 파일은 Git 밖). 과제 정답·설계 문서가 공개됨을 받아들인 결정.
- Pages 소스 = GitHub Actions(`.github/workflows/pages.yml`, 수동 실행). 전송 주소는 저장소 변수 `VITE_SUBMIT_ENDPOINT`(Settings → Secrets and variables → Actions → Variables)로 주입. 로컬 `.env.production`과 같은 값이어야 한다.
- 실행: Actions 탭 → pages → Run workflow(또는 `gh workflow run pages.yml`). 사이트 `https://ya2suho1004.github.io/chassis-3d-lab/`.
- 이후 D01을 이 출처에서 다시 실행해 D10(실제 HTTPS 출처·학교 기기)으로 넘어간다.

## 4. 운영 한계 문구(화면 하단에도 표시)

이 직접 제출 경로는 로그인 없는 공개 수신점이다. 세션 코드·익명 코드·UUID·해시는 학생 신원을 인증하지 않는다. 유효한 모양의 위조 요청과 서비스 한도 소진을 완전히 막을 수 없다. receipt는 특정 내용의 접수 확인이며 실제 학생 수행·정답·연구 참여 적격성의 증명이 아니다. 시험 통과는 연구 적용·운영 배포 승인과 구분한다.
