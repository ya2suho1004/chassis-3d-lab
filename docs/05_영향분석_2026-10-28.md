## 1. 결론

- **그대로 쓰는 것:** 판정 엔진(`src/domain`), 기록 계약 record 1.1.0, IndexedDB 선저장·재전송·CSV 백업(`src/records`), 전송 클라이언트와 응답 검증(`src/delivery/submit.ts`, `jcs.ts`), 교사 확인 0A·0E 결과.
- **새로 만드는 것:** ① Supabase 수신 서버(Edge Function + Postgres 표) ② AI 교관 챗봇(서버 함수, 대화 창, 대화 기록 계약) ③ 교사 인증과 교사용 대화 열람·챗봇 켜고 끄기 ④ 5차시용 시작 화면 흐름 ⑤ 3D 표현층 개선.
- **보관(더 쓰지 않음)으로 돌리는 것:** Apps Script 수신점(`server/apps-script/`), 관련 빌드 스크립트·시험 8개, 0C 전송 시험 문서(Apps Script·GitHub Pages 전용).
- 전송 클라이언트는 "고정 주소 1개로 JSON을 보내고 응답을 엄격히 검증"하는 구조라 수신처에 묶여 있지 않다. 그래서 학생 화면 쪽 변경은 주소 설정과 CORS 확인 정도로 작다. 서버 쪽 JCS→SHA-256 계산은 이미 TypeScript로 있는 `src/delivery/jcs.ts`를 Edge Function(Deno)에서 그대로 재사용할 수 있어, 양끝 해시 대조 계약을 유지하기 쉽다. [구현 시 Deno 호환 확인]
