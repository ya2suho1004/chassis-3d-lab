학교 Wi-Fi에서는 vercel.com 관리 화면이 막힌다. 1~3단계는 집 Wi-Fi나 휴대폰 LTE에서 한다. 배포가 끝난 `*.vercel.app` 주소는 학교 Wi-Fi에서도 열린다(10-28 확인).

## 이미 준비된 것 (Claude, 10-28)

| 항목 | 상태 | 증거 |
|---|---|---|
| `vercel.json` | 추가함. Vite, `npm run build`, 출력 `dist`, 검색 제외·보안 머리글 | 저장소 루트 |
| 운영 빌드 주소 | Apps Script → Supabase로 교체 | 빌드 결과에 `functions/v1/submit` 있음, `script.google.com` 없음 |
| 운영 빌드 연결 시험 | 허용 주소(localhost:5174)에서 submit·chat 응답을 읽음 | 기록이 남지 않는 잘못된 요청으로만 시험 |
| 3D 조명 파일 | 운영 빌드에서 200, 1.6MB | 같은 시험 |

## 1. 프로젝트 가져오기 (사용자, 학교 밖)

1. vercel.com에 로그인 → **Add New… → Project**
2. GitHub 저장소 **ya2suho1004/chassis-3d-lab** → **Import**
3. Framework Preset이 **Vite**로 잡혔는지만 본다. Build/Output 칸은 그대로 둔다(`vercel.json`이 정한다).
4. 아직 **Deploy를 누르지 말고** 2단계 환경변수를 먼저 넣는다.

## 2. 환경변수 4개 (모두 공개 값, 비밀 아님)

Environment Variables 칸에 아래 이름으로 넣는다. 적용 범위는 Production·Preview 둘 다.

| 이름 | 값 |
|---|---|
| `VITE_SUBMIT_ENDPOINT` | `https://awzualempzrroyouwwoi.supabase.co/functions/v1/submit` |
| `VITE_CHAT_ENDPOINT` | `https://awzualempzrroyouwwoi.supabase.co/functions/v1/chat` |
| `VITE_SUPABASE_URL` | `.env.local`의 같은 이름 값 |
| `VITE_SUPABASE_ANON_KEY` | `.env.local`의 같은 이름 값(anon 키는 공개용이다. RLS가 막는다) |

넣으면 안 되는 것: `GEMINI_API_KEY`, service_role 키, DB 비밀번호. 이 값들은 Supabase 비밀값에만 있다. `VITE_`로 시작하는 값은 학생 화면에 그대로 실리므로 비밀을 넣으면 공개된다.

`.env.local` 값 두 개를 클립보드로 옮기는 명령(맥북 터미널):

```bash
grep '^VITE_SUPABASE_URL=' "/Users/jamingchu/claude code/chassis-3d-lab/.env.local" | cut -d= -f2- | pbcopy
```

```bash
grep '^VITE_SUPABASE_ANON_KEY=' "/Users/jamingchu/claude code/chassis-3d-lab/.env.local" | cut -d= -f2- | pbcopy
```

## 3. 배포하고 주소 받기

1. **Deploy** → 1~2분 뒤 완료 화면
2. 고정 주소(Production Domain, 예: `chassis-3d-lab.vercel.app`)를 Claude에게 알려 준다.
   - 배포마다 바뀌는 긴 미리보기 주소는 쓰지 않는다. 미리보기 주소는 Vercel 로그인을 요구할 수 있다.

## 4. 서버 허용 주소 추가 (Claude 또는 사용자)

주소를 받으면 Supabase 함수가 그 주소의 요청만 받도록 허용 목록에 더한다. 비밀값이 아닌 설정이다.

```bash
cd "/Users/jamingchu/claude code/chassis-3d-lab" && npx supabase secrets set ALLOWED_ORIGINS=http://localhost:5174,http://127.0.0.1:5174,https://<받은주소>.vercel.app
```

이 단계 전에는 배포 화면에서 대화·전송이 "서버에 연결하지 못했습니다"로 실패한다. 정상이다.
