## 0. 정리 (Claude Code)

### 기록 창 — MOON 제안을 기본안으로
Codex도 2안(기록 창)을 권했다. 창만 만들면 막힘이 남으므로 아래를 한 묶음으로 한다.
- **창:** 기록 단계(제동력 축중·좌우 판독·계산, 최소회전반경 각도 판독·반경)에서 "수행"을 누르면 그 단계의 칸만 담은 창을 연다. 장비 근접·순서·안전 확인은 지금처럼 먼저 한다.
- **입력과 단계 완료는 따로 누른다.** 창을 열고 닫는 것만으로 제출하거나 완료하지 않는다. 최초 답(형식을 통과해 직접 제출한 첫 답)의 뜻을 지키기 위해서다. 오답이어도 단계 완료는 지금처럼 허용한다.
- **안내가 창 안에 보인다.** 정오·설명·형식 오류를 창 안에 띄우고, 실제로 보인 뒤에만 `feedbackShown`을 남긴다.
- **창과 서랍은 같은 값을 쓴다.** 제출한 값은 화면 전환·이어서 하기 뒤에도 칸에 다시 보인다. 복원 때문에 새 제출 사건을 만들지 않는다.
- **계기를 창과 함께 보인다.** 서랍에 이미 숫자 계기가 있으므로 새 정답 공개가 아니다. 칸 자동 채움, 수행 전 값 미리 보이기는 하지 않는다.
- **안내 없음도 같은 창을 쓴다.** 다음 단계는 알려 주지 않고, 정오는 기존 규칙대로 모든 최초 답 뒤에만 보인다.
- **최소회전반경 측정판 다시 보기:** 직진 복귀 뒤에도 측정 당시 눈금을 다시 볼 수 있게 한다(아래 2번).
- **태블릿:** 화면 키보드가 아래를 가려도 계기·칸·안내·버튼이 함께 보이게 한다. 창을 열면 걷기를 멈춘다.
- 새로 모으는 자료는 없다. 화면이 바뀌므로 이전 판과 이후 판 수행은 나눠 분석한다(기록에 앱 판 커밋이 남는다. 다만 옛 초안을 이어서 하면 옛 판 표시가 남는다).

## 1. Codex 답 (원문)

**2안을 권합니다. 다만 자동 완료까지 묶지 말고, 입력·피드백·보완·값 복원을 함께 해결해야 합니다.** 지정 폴더의 코드와 문서를 읽었으며 파일 수정, `.env` 접근, 네트워크 호출, 시험·빌드는 하지 않았습니다. 공개판의 배포 상태와 문서에 적힌 화면 좌표는 재확인하지 않았습니다.

먼저 바로잡을 전제가 있습니다.

- **안내 없음의 기준은 항상 “6개 응답”이 아닙니다.** 제동력은 6개, 최소회전반경은 4개입니다. 실제 코드는 해당 과제의 필수 응답 전체를 검사하므로, 일부 주석이 오래된 상태입니다. [feedbackPolicy.ts:13–17](</Users/jamingchu/claude code/chassis-3d-lab-cozy/src/domain/feedbackPolicy.ts:13>), [회전반경 과제:49–80](</Users/jamingchu/claude code/chassis-3d-lab-cozy/src/data/tasks/task.min-turning-radius.case-lv1.json:49>)
- **문서 13·16의 “피드백 정책 제안 상태”를 현재 상태로 읽으면 안 됩니다.** 후속 문서 17에서 교사 승인으로 바뀌었습니다. 다만 이것은 연구 운영·IRB 승인을 뜻하지 않습니다. [17번 문서:36–42](</Users/jamingchu/claude code/chassis-3d-lab-cozy/docs/design/docs/17_U_ITEMS_CONTRACT_REVISION_2026-10-26.md:36>)
- **`feedbackShown`은 현재도 모든 피드백의 실제 노출 기록이 아닙니다.** 사건을 먼저 기록한 다음 화면 표시를 예약하며, 정답 안내와 일부 보완 안내는 이 사건 없이 표시합니다. [TaskScreen.tsx:170–175](</Users/jamingchu/claude code/chassis-3d-lab-cozy/src/screens/TaskScreen.tsx:170>), [같은 파일:212–231](</Users/jamingchu/claude code/chassis-3d-lab-cozy/src/screens/TaskScreen.tsx:212>)

**1. 어느 안인가 — 2안을 기본으로, 해당 칸 이동 기능을 보완 경로로 붙이는 것이 좋습니다.**

1안은 빨리 적용할 수 있지만 긴 서랍을 계속 사용해야 합니다. 3안은 진입점 하나를 더 제공할 뿐, 현재 단계에 필요한 칸을 찾는 문제까지 해결하지 못합니다.

기록 창에는 다음 항목만 표시하면 됩니다.

| 과제·단계 | 표시할 입력 |
|---|---|
| 제동력 `axle` | 축중 |
| 제동력 `read` | 좌·우 제동력 |
| 제동력 `calc` | 편차·합·판정 |
| 최소회전반경 `read` | 좌·우 조향각 |
| 최소회전반경 `record` | 반경·판정 |

이 구분은 현재 엔진의 완료 조건에 이미 있습니다. 화면에서 별도 규칙을 복제하기보다 이 정의를 공통으로 사용해야 합니다. [taskEngine.ts:111–119](</Users/jamingchu/claude code/chassis-3d-lab-cozy/src/domain/taskEngine.ts:111>)

권장 동작은 다음과 같습니다.

- **열기:** 학생이 기록 단계의 버튼을 눌렀을 때 엽니다. 안내 있음에서는 버튼 이름을 “축중 기록”처럼 구체화할 수 있습니다. 안내 없음에서는 학생이 목록에서 직접 고른 단계로 열고, 다음 기록 창을 자동으로 띄우지 않습니다.
- **조건 확인:** 기존의 장비 근접·선행 단계·안전 조건을 먼저 확인합니다. 창을 만들면서 기존 제한을 건너뛰면 안 됩니다. 현재도 근접 확인 후 엔진을 호출합니다. [TaskScreen.tsx:177–188](</Users/jamingchu/claude code/chassis-3d-lab-cozy/src/screens/TaskScreen.tsx:177>)
- **제출과 완료:** 항목별 “입력”과 마지막 “단계 완료”를 유지합니다. 잘못된 답도 제출되었다면 단계 완료는 허용하고, 빈칸·형식 오류는 제출된 답으로 취급하지 않습니다.
- **닫기:** 명시적인 닫기·취소를 제공하되 닫는 행위로 제출하거나 완료하지 않습니다. 오답 설명이 나왔다고 즉시 창을 닫지 않습니다.
- **배치:** 넓은 화면은 계기와 기록 창을 나란히, 좁은 화면은 위에 계기·아래에 입력을 배치합니다. 기존 화면 위에 창만 덧씌우면 계기 가림이 반복됩니다.
- **값 공유:** 창과 서랍은 같은 입력 상태와 제출 함수를 사용합니다. `TaskScreen`을 하나 더 만들어 각각 값을 보관하는 방식은 피해야 합니다. 현재도 입력칸 상태와 제출된 응답이 따로 있습니다. [TaskScreen.tsx:153–155](</Users/jamingchu/claude code/chassis-3d-lab-cozy/src/screens/TaskScreen.tsx:153>)

편집 중인 값과 제출된 값은 구분해서 보여야 합니다. “이 기기에 저장됨”과 “이 칸의 입력을 제출함”도 서로 다른 상태입니다.

**2. 연구 타당성 — 입력 접근성은 공통으로 개선하되, 판독·제출·피드백의 뜻은 보존해야 합니다.**

**계기 값을 창에 보여도 되는가:** 현재 서랍에는 이미 숫자식 계기가 있습니다. 같은 표시를 기록 창으로 옮기는 것 자체가 새로운 정답 공개는 아닙니다. 따라서 이번에는 **현재 볼 수 있는 계기를 같은 조건으로 제공**하는 편이 적절합니다. 입력칸 자동 채움, 계산 정답 표시, 아직 수행하지 않은 측정값의 선공개는 제외해야 합니다.
