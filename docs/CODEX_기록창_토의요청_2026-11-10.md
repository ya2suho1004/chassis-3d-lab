## 2. Claude Code가 직접 재현한 것 (로컬 판, 폭 767×736, 합성 코드, 안내 있음, 제동력 사례 1)
1. 5번 단계 "조작부 AXLE Load로 축중을 확인하고 기록한다"에서 큰 버튼은 "수행"뿐입니다.
2. "수행"을 누르면 위쪽 알림에 "이 단계를 끝내려면 값을 먼저 입력하세요 / 축중 입력이 필요합니다"만 나옵니다. 입력칸으로 가는 길을 알려 주지 않고, 알림이 의뢰 카드 제목과 상태 배지를 가립니다(`src/screens/TaskScreen.tsx`의 doStep, `src/screens/LabScreen.tsx`의 g-toast).
3. 입력칸은 "작업 목록" 서랍 안에 있습니다. 서랍 내용 높이 2260px, 화면 높이 736px, 축중 칸은 위에서 1451px 지점입니다. 약 두 화면을 내려야 보입니다.
4. 학생이 해야 할 조작: 수행(안내만 나옴) → 작업 목록 → 스크롤 → 칸 누르기 → 숫자 입력 → 입력 → 서랍 닫기 → 수행. 총 7~8번입니다.
5. **입력 뒤 안내가 안 보입니다.** 일부러 틀린 값을 넣었더니 설명 글 "축중 — 다시 확인하세요"는 서랍 맨 위(화면 위로 914px 벗어남)에, 게임 알림은 서랍 뒤(z-index 6 < 8)에 떴습니다. 눈에 보이는 것은 칸 옆의 작은 ✗뿐입니다. 그런데도 기록에는 `feedbackShown`이 남습니다(TaskScreen의 `show`).
6. "계기 보기"를 누르면 계기가 크게 나오지만, 폭 767에서 의뢰 카드가 "kg" 부근을 가리고 AXLE 글자 왼쪽이 잘립니다.
7. **Claude Code가 어제 만든 결함:** 질문 버튼을 안내 줄 위로 올리면서(`.g-chatbtn` bottom:60px) 폭 약 860 미만에서 "계기 보기"(`.g-gaugebtn` bottom:64px, 가운데)와 질문 버튼이 겹칩니다. 공개판에도 있습니다. 어제 겹침을 잴 때 계기 버튼을 측정 대상에 넣지 않았습니다.
8. 기록 입력이 필요한 단계는 5개입니다. 제동력 axle·read·calc, 최소회전반경 read·record(`src/domain/taskEngine.ts`의 RESPONSE_REQUIREMENTS). 교수님 안내문에는 "작업 목록에서 각도를 넣어"라고 적혀 있지만 앱 안에는 그런 안내가 없습니다.
9. 안내 없음에서는 게임 화면에 행동 버튼이 없고(`nextActions: []`) 작업 목록의 각 줄에서 수행을 누릅니다.

## 3. 후보안 (Claude Code 초안, 더 나은 안이 있으면 제시)
- **1안 최소:** 알림에 "입력칸으로" 버튼을 넣어 서랍을 열고 해당 칸까지 스크롤하며 강조합니다. 입력 뒤 안내도 칸 옆에 보입니다.
- **2안 기록 창(MOON 제안):** 기록 단계에서 "수행"을 누르면 그 단계에 필요한 칸만 담은 작은 창이 뜹니다. 계기를 보면서 쓸 수 있게 화면을 덜 가리고, 정오·설명·형식 오류 안내도 창 안에 표시합니다. 다 쓰면 단계를 완료합니다. 서랍의 전체 기록표는 그대로 둡니다.
- **3안 상시 기록표 버튼:** 화면에 늘 "기록표" 버튼을 두고 언제든 작은 표를 엽니다.

Claude Code는 2안을 기본으로, 1안의 "안내를 보이는 곳에 띄우기"를 함께 넣자는 쪽으로 기울어 있습니다. 근거가 약하면 반박해 주세요.

## 4. 묻는 것
1. **어느 안인가.** 이유와, 놓치고 있는 함정. 창을 띄우는 조건, 닫는 조건, 계기와 창의 위치, 서랍의 입력칸과 값이 어긋나지 않게 하는 방법.
2. **연구 타당성.** 아래가 판독 활동, 최초 답 기록, 안내 없음 규칙, 사건 기록(`stepEvents`, `feedbackShown`)을 해치는지 코드와 설계 문서(`docs/design/docs/04_TASK_AND_LOG_SCHEMA.md`, 13, 16, `docs/design/CLAUDE.md`)로 판단해 주세요.
   - 창에 계기 값을 함께 보일지, 3D 계기만 보게 할지. 서랍에는 이미 숫자식 계기가 입력칸 바로 위에 있습니다.
   - 값을 넣으면 단계를 자동 완료할지, 학생이 한 번 더 눌러야 할지. 오답이어도 진행되는 현재 규칙과의 관계.
   - 안내 없음에서도 같은 창을 쓸지. 두 조건의 화면 차이를 어디까지 허용할지.
   - 재배포 뒤에도 옛 기록과 비교할 수 있는지. 새로 모으는 자료가 생기는지.
3. **태블릿 함정.** 화면 키보드가 아래 절반을 가릴 때 창과 계기 배치, 오래된 크롬, 저사양 3D, 입력 중 키보드 이동(`src/scene/Joystick.tsx`).
4. **같은 유형의 다른 막힘.** 두 과제를 안내 있음·없음으로 코드에서 끝까지 따라가 보고, "학생이 무엇을 어디서 해야 할지 모르거나 보여야 할 것이 안 보이는" 곳을 찾아 심각도 순으로 적어 주세요. 예: off 단계 하위 행동, 주변 확인, 최소회전반경 측정판 보기, 마지막 NPC 검사로 가는 길, 안내 없음에서 서랍 왕복. 위 2절에 있는 것은 빼 주세요.
5. **다음 개발 순서.** 아래 후보의 순서를 정하고 이유를 적어 주세요. 빠진 것이 있으면 넣고, 하지 말아야 할 것도 적어 주세요.
   - 기록 창(이번 안건), 계기·질문 버튼 겹침 수정
   - QR 입장 구현(`docs/superpowers/plans/2026-11-09-qr-entry.md`, 13단계, 서버 표 추가 필요)

   - E1 실제 조건 AI 시험, B2 재수행 연결(연구 결정 대기)
