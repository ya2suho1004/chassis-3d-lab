# 학생용 AI 모델 연결 준비표 (E3, 2026. 11. 9.)

> Codex 회의(11-08) E3. **모델을 새로 고르자는 문서가 아니다.** 학생 적용 후보(Anthropic 또는 OpenAI, IRB 계획서 4-3)를 키를 받는 즉시 안전하게 연결할 수 있도록, 지금 코드가 어디까지 준비됐고 무엇이 남았는지를 정리한다.
> 근거는 이 저장소 코드(브랜치 cozy-stage1, E2 반영 뒤)와 논문 폴더 IRB 초안(읽기만). 회사 약관·보관·학습 이용은 **원문 확인 전이므로 이 문서에 단정하지 않는다.**

## 2. 밖(AI 회사)으로 보내는 것 / 보내지 않는 것

모델과 관계없이 같다(`chatCore.ts` handleChat).

| 보냄 | 내용 |
|---|---|
| 시스템 프롬프트 | 역할·말투·안전 규칙, 과제의 **판정 기준과 작업 순서**(승인된 값), 지금 단계 이름, 안내 있음/없음 규칙. **학생 사례의 측정값·정답·판정은 넣지 않음**(prompt.ts 원칙) |
| 질문 | 300자 이내, 전화번호·이메일·주민등록번호·학년반번호 형식은 `[가림]`으로 바꾼 뒤 |
| 앞 대화 | 최근 3번까지 — 질문(가림 뒤)과 그때 AI 답(2,000자 이내) |

| 보내지 않음 |
|---|
| 익명 코드, 수행 기록 ID, 세션 코드, 기기 정보, 학생 측정값 |

- **남는 한계:** 이름은 형식이 없어 자동으로 가리지 못한다(mask.ts 주석). 교사 대화 점검에서 사람이 확인해야 한다.
- 우리 서버(Supabase, 서울)에 남는 것: chat_logs 표 — 가림 뒤 질문, 답, 가린 종류, 공급자·모델·모델 버전·프롬프트 버전, 걸린 시간, 상태(answered·refused·error). **모델을 바꿔도 이 형식은 그대로**라 기록에서 어느 모델 답인지 구분된다.

## 3. 키를 받으면 할 일 (순서)

### Anthropic으로 갈 때 (코드 거의 준비됨)
1. **키 보관**: 키는 Supabase 비밀값(`ANTHROPIC_API_KEY`)과 개발 PC `.env.local`에만. 채팅·화면 코드·저장소에 넣지 않는다.
2. **모델 이름 확인**: 공식 문서의 현재 모델 ID로 `ANTHROPIC_MODEL`(시험 도구)·`CHAT_MODEL`(서버)을 정한다. 시험 도구 기본값 `claude-haiku-5-5`는 자리 표시일 뿐 확인 전이다.
3. **합성 질문 시험**(실제 학생 자료 없음): `node scripts/chat-eval/run-conversations.mjs anthropic --run` → `docs/chat-eval/`에 판독표(E1, 다중 대화 12개 + 기존 질문 20개, 서버 처리 그대로). 같은 묶음을 Gemini로도 돌려 MOON이 나란히 읽고 판단. 특히 안내 없음에서 정답·다음 단계를 흘리지 않는지, 조르거나 허락을 사칭해도 유지되는지(C01·C02), 앞선 오답을 바로잡는지(C03·C04), 안전 첫 문장(C05·C06·T07·B03), 자료에 없는 내용을 지어내지 않는지(C08·C09), 관계없는 질문 거절·개인정보(C12·T15·T16).
   - 주의: 다중 대화가 실제와 같은 조건이다(Gemini 0.4.1의 11-03 결과는 답 길이 600·한 번 질문 조건이라 그대로 비교하지 않는다). 세션 설정·한도·Supabase 함수는 거치지 않으므로 전환 뒤 6단계에서 따로 확인한다.
4. **끊김·거절 확인**: 일부러 아주 짧은 길이 제한으로 한 번 불러 `max_tokens`가 '끊김'으로 처리되는지 확인(E2 규칙). 거절(refusal)이 실제로 오는지는 억지로 만들지 않는다.
5. **동시 요청**: 30명 수업을 가정해 `load.mjs`로 유료 키 한도를 확인(429 처리: 짧으면 1회 재시도, 길면 '질문이 몰려 있어요').
6. **서버 전환**(MOON 허락 뒤): Supabase 비밀값 `CHAT_PROVIDER=anthropic`, `CHAT_MODEL=…`, `ANTHROPIC_API_KEY` → chat 함수 다시 배포 → 리허설 세션(가상 코드 D-01~)으로 교사가 직접 몇 개 물어 확인.
7. **문서 맞추기**: IRB 서류의 "[모델 확정 후 기재]" 자리(Hermes), 설계 변경 기록, `scripts/chat-eval/README.md`의 "anthropic 미검증" 문구.

### OpenAI로 갈 때 (코드 작업 필요, 작음~중간)
1. 위 1·2와 같음(`OPENAI_API_KEY`, 모델 ID 확인).
2. **연결 코드 작성**: 공식 문서로 요청·응답 형식을 확인한 뒤 서버 `providers.ts`와 시험 도구 `providers.mjs`에 같은 모양(문맥 번갈아, 시스템 분리, 429 retry-after)으로 추가. `index.ts` KEY_ENV에 `openai: 'OPENAI_API_KEY'`.
3. **끝난 이유 연결**: `classifyFinish`에 OpenAI의 '길이로 끊김' 값(예: `length`)을 끊김에, '내용 필터' 값을 막힘에 넣고 시험 추가. 이 단계를 빠뜨리면 끊긴 답이 모두 '답할 수 없어요'로 바뀐다.
4. 이후 Anthropic의 3~7과 같음.

## 4. 원문으로 확인할 것 (MOON·Hermes — IRB 4-3·설명문의 [원문 확인] 자리)
회사별로 공식 약관·정책 원문에서 확인해 출처(주소·확인 날짜)와 함께 적는다. 이 문서는 값을 채우지 않는다.

| 확인 항목 | Anthropic | OpenAI |
|---|---|---|
| 18세 미만 학생이 쓰는 서비스에 API 사용 가능 조건(학교·교육 용도, 보호자 동의 등) | | |
| API 입력·출력의 모델 학습 이용 여부(기본값, 끄는 방법) | | |
| 회사 보관 기간·예외 보관(남용 감시 등)·삭제 요청 가능 범위 | | |
| 처리 국가(국외 이전 고지: 이전 국가·수신자·시기·방법·목적·보유 기간) | | |
| 결제 방식·학교 회계로 가능한지, 사용 한도 설정 | | |

## 5. 하지 않을 것
- 학생 자료로 모델을 비교하지 않는다(합성 질문만).
- 끝난 이유·모델 비교 결과를 학생 기록에 새로 저장하지 않는다(새로 모으면 IRB 수정).
- 판정·채점·안전 승인을 AI에 맡기지 않는다(Codex 회의 "하지 않음").
- 키를 화면 코드·저장소·채팅에 두지 않는다.

## 6. 미리 해 둘 수 있는 것 (키 없이, 작음)
- OpenAI 연결 코드 초안 + 가짜 응답 시험(형식은 공식 문서 확인 뒤). MOON이 OpenAI 쪽으로 기울면 진행.
- 실제 조건 시험 묶음과 판독표: E1에서 완료(`scripts/chat-eval/run-conversations.mjs`). 실제 호출은 MOON 허락 뒤.
