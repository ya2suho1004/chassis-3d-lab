## 2. 확정된 범위

- 한국어 문서·설명. 전문용어는 첫 등장 때 쉬운 풀이 한 줄.

- 첫 MVP는 제동력 측정 및 판독 한 과제. 실제 학교 배치를 최대한 재현한다. 2026-10-20 기준 번호 사진 44장·손 스케치 1장이 있고 주요 장비의 상대 배치는 정리됐다(`../review/layout-review.txt`). 실측 치수·개방 연결부·학생 시작점은 미확정이며 `layoutConfirmed=false`다. 북쪽·동쪽은 막힌 면, 남쪽·서쪽은 엔진·전기 실습 구역과 개방 연결된 열린 면이고 섀시 구역 별도 입구를 만들지 않는다.
- 1인용, 설치 없는 일반 브라우저, PC와 태블릿. 멀티플레이·ZEP·HMD·초기 3인 1조 역할 모드 제외.
- 안내 연습과 무안내. 시간제한 평가는 후속이며 MVP에서 비활성.
- ‘예습/복습’은 수업에서 쓰는 시점(대기 중 예습 → 실제 실습 → 실습 후 복습)이고, ‘안내/무안내’는 도움 제공 방식이다. 두 개념을 같은 모드 이름으로 합치지 않는다. 교육적 효과는 연구에서 검증할 가설이며, 흥미나 앱 통과율만으로 실제 실습 능력 향상을 입증했다고 쓰지 않는다.
- 설명적 피드백. 학생의 최초 응답을 보완 응답으로 덮어쓰지 않는다.
- 온라인 자동 제출, 브라우저 선저장(현재 추천: IndexedDB), 서버 접수번호, 동일 ID 중복 방지, 재전송, CSV 비상 백업.
- 이름·이메일·전화번호·학번 원본 수집 금지. 가명 코드도 연구자 대응표와 연결될 수 있으므로 ‘완전 익명’이라고 표현하지 않는다.

## 3. 추천 구조와 변경 규칙

추천은 React/Vite/TypeScript, Three/R3F/Drei 일부, reducer/context, IndexedDB, Apps Script/교사 비공개 Sheet다. 2026-10-20 사용자 결정으로 호스팅·제출 경로는 **GitHub Pages + Apps Script 직접 호출**을 먼저 시험하고, 실패하면 같은 출처 중계(Cloudflare Pages Functions)로 전환한다. 이 구조는 설계 추천이며 계정 연결·학교기기 동작·비용이 검증된 제품이 아니다.

버전은 구현 시 공식 호환성과 기존 환경을 확인한 뒤 lockfile로 고정한다. 설치·테스트·배포 명령이 필요한 단계에서는 작업 전 환경을 점검한다. 사용자가 승인한 구현 범위를 넘어 물리 엔진·LLM NPC·일반 수식 실행기·범용 대시보드를 추가하지 않는다.

과제 엔진·판정·화면·3D·기록·전송을 분리한다. 학생 위치 같은 프레임별 값은 연구 상태에 넣지 않는다. 과제·기준·피드백·NPC 대사·배치는 데이터로 분리하되 새 물리 동작까지 데이터만으로 구현된다고 주장하지 않는다.

## 5. 판정과 학습기록의 필수 계약

- 기존 `judge.js`를 그대로 복사하지 않는다. 누락 기준의 자동 8/20/50 대입, 음수 입력 합격, 알 수 없는 위치를 뒤축으로 처리, 공백/Infinity, 표시 반올림 문제를 회귀검증한다.
- 기준·출처·차량·시험조건·단위·경계·반올림이 미승인이면 공식 평가 차단. NCS에 적힌 숫자를 학교 승인값이나 현행 법정기준으로 자동 채택하지 않는다.
- 실제 배치 좌표·치수는 실측 전 `null`, `layoutConfirmed=false`. 사진·스케치 기반 상대 배치 초안은 ‘임시 개념 배치’로 표시하고 실측 좌표와 분리한다. 모눈 한 칸을 미터로 환산하지 않는다.
- 26번 사진의 ‘후 제동력 좌 240kg·우 200kg·후축중 600kg’은 학생에게 제시하는 고정 예시값이다(사용자 확정). 실제 측정값·합격 기준이 아니며 kg 표기를 kgf·N으로 바꾸지 않는다. 종이의 ‘소수 첫째 자리 기재, 둘째 자리 절사’는 적용 범위(중간 계산/최종 기재/판정)가 미확정이다.
- 14번 사진의 노란 ABS TESTER 조작부는 27·28번 제동력 롤러 장비와 함께 쓴다(사용자 확정). 버튼 순서·작동 화면은 기자재 고장으로 미확인이며, 이 고장이 가상 과제를 폐기하거나 가상 장비를 고장 상태로 만들라는 뜻은 아니다.
- 수행 시작 시 승인 `sessionSnapshotId`와 모든 버전·모드를 고정하고 `recordId`를 한 번 만든다. 최초 draft 저장에 실패하면 이후 진행을 막고 같은 ID로 복구한다.
- `vehicleVerdict`는 차량, `judgmentCorrect`는 최초 학생 판정, `npcInspectionResult`는 최종 수행이다. 불량 차량을 정확히 판정하면 NPC 통과가 가능하다.
- `measurementInputs`, `calculationAnswers`, `judgmentAnswers`의 최초/최종 응답과 단위를 보존한다. 임의 100점·감점식·대표 수행 선택을 만들지 않는다.
- `retryCount`는 학습 재수행, `npcInspectionCount`는 같은 수행의 재검사, `uploadAttemptCount`는 전송 시도다.
- 연구 결과는 불변 `recordPayload`, 저장·접수는 `deliveryEnvelope`. `feedbackShown`은 실제 표시 직후 기록하며 읽음 증거로 보지 않는다.
- `configurationApproval.researchUseApproved`는 별도 연구자 허용 확인이다. 콘텐츠·배치 승인만으로 연구사용을 허용하지 않으며 이 플래그가 IRB·동의를 대신하지 않는다.
- `displayMode`는 시작 모드, `experiencedDisplayModes`와 전환 이벤트로 3D/도식 혼합을 식별한다. 도식 모드의 공간학습 동등성을 가정하지 않는다.

## 6. 저장·접수·공용 기기

트랜잭션 `complete` 이후에만 전송한다. 네트워크를 IndexedDB 쓰기 트랜잭션 안에서 기다리지 않는다. `no-cors`, fetch resolve, iframe load, HTTP200만으로 제출 완료를 표시하지 않는다. 같은 ID·같은 payload는 같은 receipt, 다른 내용은 충돌이며 덮어쓰기나 새 ID 자동 우회를 금지한다.

JCS(RFC8785)→UTF-8→SHA-256 규약을 양끝에서 대조한다. Unicode 자동 정규화를 하지 않는다. 서버 비밀은 서버에만 둔다. 학생 코드·프론트 환경변수·URL·로그에 비밀을 넣지 않는다. 공개 API에는 연구결과 전체조회·교사 설정 변경을 제공하지 않는다.

다음 학생 시작 시 화면·현재 상태는 초기화하되 과거 미접수 outbox를 보존한다. 과거 payload는 원래 코드로 전송한다. 학생 화면에서 다른 학생 기록을 열람·일괄 내보내기하지 않는다. 메뉴 숨김이나 공통 PIN을 강한 권한 통제로 주장하지 않는다.

초기 한도 제안은 canonical payload32KiB, POST48KiB, 의미 이벤트200개다. 실제 셀·브라우저·계정·부하 시험 후 조정한다. 중요한 사건을 잘라 한도에 맞추지 말고 원본 보존·수집중단·교사 확인 흐름을 둔다.

## 7. 구현·테스트·커밋

구현은 `06_MVP_ROADMAP.md`의 한 단계씩 진행하고 각 단계의 완료 증거를 확인한다. 먼저 규칙·저장·접수 실패를 검증하고, 이어 실제 배치·캐릭터·상호작용을 붙인다. 검증용 데이터는 가짜 코드이며 실제 학생 적용은 연구자 확인 이후다.

필수 검증은 잘못된 기준/단위 차단, 계산 경계, 첫/최종 답, 불량 차량 정답 통과, 초안 복원, 저장 실패, 다른 학생 전환, 응답 유실·동시 재전송·내용 충돌, 잘못된 ack, 용량 상한, 실제 기기의 키보드·터치·WebGL 장애다. 스키마 검사나 문서 검토를 실행 앱 검증으로 보고하지 않는다.

커밋은 사용자가 승인한 해당 프로젝트 안의 변경만 작고 검토 가능한 단위로 묶는다. 먼저 diff와 개인정보·비밀 포함 여부를 확인하고, 관련 검증 결과를 커밋 설명에 남긴다. 무관한 변경·원본 자료·생성된 학생 결과·비밀은 포함하지 않는다. 기존 변경을 지우거나 강제 reset하지 않는다. push·배포는 별도 사용자 권한 범위다.

보고는 ‘변경한 것 → 확인한 증거 → 미확정/실패 → 다음 한 단계’ 순서로 짧게 한다. 실제 실행하지 않은 것을 성공했다고 말하지 않는다.
