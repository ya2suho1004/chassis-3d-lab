# 00 프로젝트 개요

작성일: 2026-10-16 · 현장자료 반영 수정 2026-10-20(v0.2, [변경 기록](10_CHANGELOG_2026-10-20.md)) · 상태: 교사 검토용 · 앱 구현 전

## 먼저 읽을 내용

이 프로젝트는 **실제 학교 실습장의 배치와 장비 위치를 최대한 재현하는, 1인용 브라우저 기반 3D 게임형 가상 실습장 시뮬레이션**을 목표로 한다. 학생이 캐릭터를 움직여 NPC 교관에게 과제를 받고, 제동력 측정 절차와 측정값 판독·계산·판정을 연습하도록 한다. 실제 차량 정비 실습을 대체한다고 주장하지 않는다.

첫 버전은 **공간은 실제 학교를 기준으로, 작동하는 실습 과제는 ‘제동력 측정 및 판독’ 하나**로 제한한다. 실제 장비의 위치를 보여주는 것과 모든 장비의 정비 기능을 구현하는 것은 구분한다. 2026-10-20에 번호 사진 44장과 손 스케치 1장을 확보해 주요 장비의 상대 배치는 정리했다(`../../review/layout-review.txt`). 실제 길이·폭·높이, 기둥 간격, 장비 간 거리, 통로 폭, 개방 연결부 범위, 학생 과제 시작점은 미확정이므로 좌표와 치수는 아직 확정하지 않았다(`layoutConfirmed=false`).

이번 결과물은 요구사항, 게임 흐름, 기술 구조, 데이터 계약, 연구기록 제출, 개발 순서와 Claude Code 인수 지침이다. 실행 앱·온라인 제출 서버·외부 저장소·배포 환경은 만들지 않았다.

## 0. 연구의 출발점 (2026-10-20 사용자 설명)

친환경자동차과는 자동차를 실습 기자재로 쓰므로 학생 1인당 1기자재를 확보하기 어렵고 공간도 좁다. 교사는 기자재 수에 맞는 일부 학생만 실습장으로 데려가 지도하고, 나머지는 별도 강의실에서 대기한다. 대기 학생에게 수업 공백이 생기고, 순번이 늦으면 첫 설명을 잊어 교사가 같은 설명을 반복하며, 그만큼 실제 실습 시간이 줄어든다.

가상 실습장은 **대기 학생이 실습장과 비슷한 3D 공간에서 NPC에게 오늘의 과제를 받아 장비 위치와 실습 과정을 미리 익히고, 실습을 마친 학생이 복습하도록 돕는 도구**다. 핵심 흐름은 ‘대기 중 예습 → 실제 실습 → 실습 후 복습’이다. ‘예습/복습’은 수업에서 쓰는 시점이고 ‘안내/무안내’는 도움 제공 방식이므로 두 개념을 같은 모드 이름으로 합치지 않는다.

교육적 효과는 연구에서 검증할 **가설**이다. 검토 후보는 실제 실습 준비도, 장비 찾기, 절차·안전 수행, 판독·계산·판정 정확성, 학습 내용 유지(학습 효과)와 반복 설명·교사 개입 감소, 실제 실습 시간 확보(수업 운영 효과)다. 앱 내 통과율이나 흥미 설문만으로 실제 실습 능력 향상을 입증하지 않는다. 비교집단·측정도구·표본수·분석계획은 이 문서로 확정하지 않는다.

## 2. 학습목표와 최소 성공 기준

학생이 ① 실습장에서 제동력 시험기와 관련 장비의 위치를 찾고, ② 승인된 작업·안전 순서를 수행하며, ③ 제시값을 판독하고 승인된 수식으로 계산한 뒤 ④ 기준과 비교하여 이유를 설명하도록 한다. ‘걸어 다녔다’나 ‘NPC와 대화했다’ 자체를 학습성과로 계산하지 않는다.

| 관점 | MVP 성공 기준 |
|---|---|
| 공간 | 교사가 실제 배치와 비교해 외곽·주요 출입구·고정장비·핵심 동선의 일치 여부를 검토하고 승인한다 |
| 학습 | 안내 연습과 무안내 수행이 같은 절차·판정 규칙을 사용한다. 첫 응답과 보완 응답을 구분한다 |
| 안전 | 위험한 행동 시도를 차단하고 이유와 복구 방법을 설명한다. 경고를 끄는 모드는 제공하지 않는다 |
| 판정 | 승인된 기준·단위·적용 조건이 없으면 ‘불량’ 대신 ‘판정 불가’로 처리하고 연구평가 진입을 막는다 |
| 기록 | 새로고침 후 현재 수행이 복원된다. 확정 결과는 로컬 저장 완료를 확인한 뒤 전송한다 |
| 접수 | 서버 저장 후 응답 유실·동시 재전송에도 동일 `recordId`·동일 내용은 같은 접수번호를 반환한다 |
| 운영 | 교사가 개발자 도구 없이 수업 설정을 확인하고 접수 목록·누락 후보·현재 수행 CSV를 점검할 수 있다 |
| 현장 | 실제 학교 PC와 태블릿에서 키보드·터치·네트워크 장애 시험을 통과한다. 현재 실측 결과는 없다 |

교육효과가 통계적으로 유의하다는 조건은 제품 수용 기준으로 미리 보장하지 않는다. 비교학급에는 앱 로그가 없으므로, 앱 로그가 없는 것을 수행 오류 0회로 해석하지 않는다. 학급 간 효과 비교에는 공통 사전·사후 검사 등 별도의 연구도구가 필요하다.

## 3. 범위

포함: 실제 공간 조사와 배치 모델, 작은 기능 범위의 3D 실습장, 학생 캐릭터, NPC 1명, 제동력 과제 1개, 안내/무안내, 절차·안전 인터록, 판독·계산·판정, 설명적 피드백, NPC 보완·통과, 결과 요약, 로컬 저장, 자동 제출과 접수 확인, 재전송, CSV, 교사 설정·운영 절차이다.

후속 버전: 디스크 두께·런아웃, 페달 유격, 주차 브레이크 클릭 수, 톤 휠 간극 등의 과제와 시간제한 평가이다. 기존 연산·상호작용 유형에 맞는 과제는 데이터 추가를 중심으로 확장한다. 새로운 측정기 동작이나 연산이 필요한 과제까지 코드 변경 없이 된다고 약속하지 않는다.

제외: 멀티플레이, ZEP, HMD, 초기 3인 1조 역할 모드, 실시간 생성형 AI 교관, 차량 전체 물리 시뮬레이션, 충돌·상해 재현, 학생 로그인 강제, 이름·연락처·학번 원본 수집, NCS 그림·사진·표의 재배포이다.

## 4. 추천 구조를 쉬운 말로 설명하면

화면과 3D는 React와 Three.js로 만들고, **과제 규칙을 3D에서 분리**한다. 장비 외형을 바꾸어도 판정은 같아야 하고, 저사양 기기의 도식 화면에서도 같은 입력과 피드백을 사용할 수 있어야 한다. 도식 화면 이용 여부는 기록하여 공간학습 경험의 차이를 구분한다.

기록은 IndexedDB라는 브라우저 내부 저장소에 먼저 넣는다. 자동 제출은 같은 웹주소의 작은 중계 기능을 거쳐 교사 소유 Google Sheet에 보낸다. Apps Script는 구글 시트에 결과를 기록하는 서버 프로그램이다. 학생은 Google 계정으로 로그인하지 않고, 교사는 본인 계정으로 설정과 결과를 관리한다. 이 구성은 **운영 계정·학교 정책·실제 제출 시험 전까지 검증된 연결이 아니다**.

호스팅 추천은 Cloudflare Pages와 Pages Functions이다. GitHub Pages는 정적 화면 배포 대안이지만, 단독으로 서버 접수 확인까지 갖춘 전체 구조는 아니다. 계정 개설·요금제·결제·배포 설정 변경은 이번에 수행하지 않는다. 무료 운영을 보장하지 않는다.

## 5. 중요한 보완 결정

1. **실제 배치 재현을 독립 작업으로 관리한다.** 촬영·실측 → 배치 데이터 → 교사 비교검토 → 3D 배치 순서로 진행한다. 단순 가상 공간을 실제 학교 공간인 것처럼 제시하지 않는다.
2. **최초 성과를 보존한다.** 실전에서 틀린 뒤 보완하여 통과해도 첫 답을 정답으로 덮어쓰지 않는다. 학습 재수행과 전송 재시도를 서로 다른 필드에 기록한다.
3. **기존 판정 코드를 그대로 가져오지 않는다.** 기준값 기본 대입을 제거하고 음수·잘못된 축 위치 등의 입력 검증을 보완한 뒤 승인된 수식으로 검증한다.
4. **실습 통과와 제출 접수를 구분한다.** ‘실습 통과 / 기기 저장됨 / 서버 접수 확인됨’은 각각 별도 상태다.
5. **공용 기기를 고려한다.** 다음 학생 시작 시 화면과 현재 입력은 초기화하되 이전 학생의 미접수 기록은 원래 코드와 내용으로 대기열에 남긴다.
