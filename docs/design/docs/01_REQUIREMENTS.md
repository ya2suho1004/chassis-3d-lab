# 01. 요구사항과 수용 기준

> 설계 검토본 v0.1 · 2026-10-16 · 현재 단계는 문서와 인터페이스 계약 작성이며 앱·빈 스캐폴딩은 구현하지 않는다.

이 실습장은 학생 한 명이 학교 실습장을 재현한 공간에서 제동력 측정·판독을 연습하는 브라우저 게임이다. 교사는 ‘화면이 보이는가’와 함께 ‘학생이 어떤 절차와 판단을 수행했고 기록이 실제 접수되었는가’를 확인할 수 있어야 한다. 아래 수용 기준은 구현 후 합격 여부를 눈으로 확인하거나 결과 기록으로 검증할 수 있게 적었다. **이 문서의 검증 항목은 아직 실행하지 않았다.**

연결 문서: [프로젝트 개요](00_PROJECT_BRIEF.md) · [게임 흐름](02_GAME_FLOW_AND_STORYBOARD.md) · [구조](03_TECH_ARCHITECTURE.md) · [데이터 계약](04_TASK_AND_LOG_SCHEMA.md) · [제출 흐름](05_RESEARCH_DATA_PIPELINE.md) · [구현 순서](06_MVP_ROADMAP.md).

## 1. 결정의 상태

| 등급 | 내용 |
|---|---|
| 확정 | 1인용 브라우저 기반 3D 게임형 가상 실습장 시뮬레이션, 학생 캐릭터와 NPC 교관, 제동력 과제 하나, 안내/무안내 모드, 설명적 피드백, 로컬 선저장·온라인 접수 확인·재전송·CSV |
| 사용자 추가 확정 | 실제 학교 실습장 배치를 최대한 재현. 2026-10-20 사진 44장·손 스케치로 상대 배치는 정리됐으나 실측 치수·연결부·학생 시작점이 미확정이라 `layoutConfirmed:false`이다. 북쪽·동쪽은 막힌 면, 남쪽·서쪽은 엔진·전기 실습 구역과 개방 연결된 열린 면이며 섀시 구역 별도 입구를 만들지 않는다. MVP의 작동 과제는 제동력 하나, 다른 장비는 위치·명칭 학습용 |
| 제안 | 캐릭터가 보이는 3인칭, 흔들림 없는 카메라, 키보드·마우스와 터치의 동등한 핵심 조작, IndexedDB 저장, 같은 출처의 제출 중계 사용 |
| 교사 확인 필요 | 학교 차량·시험기, 안전 및 조작 순서, 판독 단위·정밀도, 수식·기준·반올림, 실제 배치자료와 재현 검토 |
| 연구자 확인 필요 | 대표 수행 선택, 최초/최종 응답 분석, 배점 유무, 힌트 허용, 수업·평가·면담 시기, 두 학급 조건, IRB 관련 보관·접근·폐기 |

과거 자료의 ‘학생 캐릭터 또는 1인칭’ 선택지는 캐릭터 필수 결정을 삭제하는 근거가 아니다. 기본 시점은 3인칭으로 제안한다. 1인칭 전용으로 바꾸려면 학생 캐릭터 요구를 어떻게 충족하는지 교사가 별도 검토해야 한다.

## 2. 범위와 핵심 용어

- MVP는 작은 실습장 한 곳, 학생 캐릭터, NPC 한 명, `taskId:braking-force` 한 과제이다. 다른 고정장비는 위치 학습용 단순 모델로 보일 수 있으나 정비 과제를 모두 구현하지 않는다.
- `difficultyMode`는 `guided | unguided | timedAssessment`이다. 시간제한 평가인 `timedAssessment`는 후속 버전이며 MVP에서는 선택할 수 없다.
- 수업 시점 ‘예습(대기 중)/복습(실습 후)’은 `difficultyMode`와 다른 축이다. 현재 계약에는 해당 필드가 없으므로 [04 §12](04_TASK_AND_LOG_SCHEMA.md)의 `usagePhase` 제안을 버전 변경과 함께 검토한다. 채택 전까지는 세션 코드 규칙으로 구분한다.
- `attemptRole`은 `practice | primary | remediation`이다. 이는 수행의 목적이며 분석 대상 자동 선정 규칙이 아니다. 공식 무안내 최초 성과를 주 분석 후보로 삼는 것은 제안이다.
- `recordId`는 한 학습 수행이 시작될 때 한 번 발급하는 UUID, 즉 충돌 가능성이 매우 작은 식별자이다. 전송 재시도와 새로고침 복원에서는 바꾸지 않고, 새 학습 수행에서만 새로 만든다.
- `recordPayload`는 확정한 연구 내용, `deliveryEnvelope`는 저장·전송 상태이다. 전송 상태를 갱신해도 확정 연구 내용은 바뀌지 않는다.
- `sessionSnapshotId`는 교사가 공개한 불변 수업 설정의 UUID이다. 수업 설정·연구정책·피드백정책 버전과 승인 상태를 이 스냅샷에 연결한다.
- `displayMode`는 시작 화면모드인 `threeD | diagram`, `experiencedDisplayModes`는 실제 경험한 모드의 배열이다. 전환 시점은 이벤트로 남긴다. `diagram`은 경량 평면 모드이며 같은 판정 규칙을 써도 3D 공간학습과 동등하다고 간주하지 않는다.
- `vehicleVerdict`는 측정 대상의 `pass | fail | null`, `judgmentCorrect`는 학생 최초 판정의 정오/null, NPC 결과는 최종 수행 검사이다. 세 결과를 서로 대입하지 않는다.
- 이름 대응표가 게임 밖에 존재하므로 `anonymousStudentCode`는 재연결 가능한 가명 코드이다. 개인정보를 완전히 익명화했다고 표현하지 않는다.

## 3. 학생 기능

| ID | 요구사항 | 관찰 가능한 수용 기준 |
|---|---|---|
| ST-01 | 수업 세션·익명 코드 입력 및 형식 검사 | 교사가 배포한 코드 규칙에 맞지 않으면 시작이 차단되고 수정 방법이 표시된다. 이름·이메일·학번·전화번호 입력란은 없다. 코드 형식 검사를 본인 인증이라고 표시하지 않는다 |
| ST-02 | 학생 캐릭터 입장·이동·카메라 | 학생 캐릭터를 조작하여 NPC와 시험기에 도달한다. 키보드/마우스와 터치로 같은 필수 행동을 완료한다. 기본 카메라 흔들림·강제 급회전은 없다 |
| ST-03 | NPC 접근·과제 수령 | 접근 후 의도적인 대화 조작으로 목표·과제·모드를 확인한다. 대화 중 중복 수령으로 recordId가 추가 생성되지 않는다 |
| ST-04 | 목표·진행 표시 | 과제명·현재 모드·현재 학생 코드·현재 단계·다음 행동을 확인할 수 있다. 무안내에서는 정답 순서를 미리 알려주지 않는다 |
| ST-05 | 장비 위치 탐색 | 제동력 시험기를 다른 위치 학습용 장비와 구별한다. 접근만으로 장비를 자동 작동시키지 않는다 |
| ST-06 | 장비 상호작용 | 조작 가능한 장비와 행동이 글자·아이콘으로 표시된다. 대화창/입력창 사용 중 캐릭터 이동이 의도치 않게 발생하지 않는다 |
| ST-07 | 안전수칙·인터록 | 필수 안전 확인 또는 장비 준비 조건을 누락하고 작동하면 해당 행동이 차단되고 잘못된 점·이유·수정 방법이 표시된다. 안내가 없는 모드에서도 안전 경고는 유지된다 |
| ST-08 | 안내/무안내 분리 | `guided`에서는 절차 안내를 제공한다. `unguided`에서는 다음 정답 행동을 자동 제시하지 않는다. 진행 중 모드 변경은 새 수행 시작을 요구한다 |
| ST-09 | 순서 판정 | 승인된 단계의 선행 조건을 건너뛴 행동은 정의된 오류 코드로 기록되고 다음 단계가 무조건 완료되지 않는다. 자유 탐색과 절차 오류를 구별한다 |
| ST-10 | 측정 제시·판독·입력 | 시나리오 원시값과 학생 입력이 별도로 남는다. 단위·자리수·허용오차는 승인된 데이터에서 읽고 빈 단위나 추측값으로 채점하지 않는다 |
| ST-11 | 편차·합 계산과 양호/불량 판정 | `calculationAnswers`에 편차·합의 첫/최종 입력·단위·정오를, `judgmentAnswers`에 첫/최종 판정 답을 각각 보존한다. 학생이 제출한 뒤 시스템 정답과 설명을 공개하며 미응답은 null이다. 정정이 첫 답을 덮어쓰지 않는다 |
| ST-12 | 설명적 피드백 | 오류의 원인·수정 행동을 표시하며 승인된 feedbackPolicyVersion의 공개 시점을 따른다. `feedbackShown`에 feedbackKind·feedbackKey·해당 시 itemId와 시점을 남긴다. 무안내에서도 안전 경고는 유지한다 |
| ST-13 | NPC 검사·보완·재검사 | `passed | needsCorrection | notCompleted`를 구분한다. NPC는 최종 응답·완료 절차·안전조건을 검사하며 최초 오답이나 vehicleVerdict:fail만으로 계속 실패시키지 않는다. 보완은 오류 단계에 연결하며 npcInspectionCount를 남긴다 |
| ST-14 | 수행 결과 요약 | 활성 학습시간, 비안전 오류, 안전 위반, 요청 힌트, 첫 답/최종 답, NPC 검사 결과가 구별되어 보인다. 근거 없는 총점·감점식은 없다 |
| ST-15 | 로컬 선저장 | 새 수행 draft를 먼저 저장하고 핵심 사건마다 갱신한다. 최초 draft 저장에 실패하면 안전·장비 수행으로 넘어가지 않고 복구를 안내한다. 결과 확정 내용의 저장 transaction 완료 전 온라인 전송을 시작하지 않는다 |
| ST-16 | 온라인 접수 확인 | 성공 응답의 recordId·receiptId·payloadHash를 확인한 뒤 `acknowledged`와 접수번호를 표시한다. NPC 통과·HTTP200·응답 없는 전송을 제출 성공으로 표시하지 않는다 |
| ST-17 | 실패·응답 유실 재전송 | 인터넷을 끊으면 `pending`이 유지되고, 서버 저장 뒤 응답을 유실시키면 `confirmationPending`이 된다. 같은 ID·내용 재전송 후 접수번호가 동일하고 정본은 한 건이다 |
| ST-18 | CSV 비상 백업 | 현재 수행의 CSV에 recordId·버전·연구 내용·접수 상태를 포함한다. 온라인 자료와 합칠 때 ID 기준으로 중복 제거할 수 있다. 다운로드 성공을 온라인 접수 성공으로 표시하지 않는다 |
| ST-19 | 중단·재개·학생 전환 | 새로고침 후 같은 draft를 선택하여 재개한다. 다음 학생 시작 시 이전 입력·결과 화면이 사라져도 미전송 대기열은 보존된다. 이전 코드와 일치한다고 다른 세션 기록을 자동 복원하지 않는다 |
| ST-20 | 경량/평면 모드 | WebGL 실패나 심한 성능 저하 시 설명과 diagram 경로를 제공한다. 시작 displayMode는 바꾸지 않고 experiencedDisplayModes를 갱신하며 displayModeChanged에 fromDisplayMode·toDisplayMode·시점·이유를 남긴다 |

## 4. 교사 운영 기능

| ID | 요구사항 | 관찰 가능한 수용 기준 |
|---|---|---|
| TE-01 | 수업 세션·과제·모드 설정 | 교사 계정으로 보호된 Sheet 설정 탭과 ‘검사 후 수업 공개’ 메뉴로 세션·코드 규칙·제동력 과제를 준비하고 sessionSnapshotId를 부여한다. 학생 앱은 공개 스냅샷만 읽고 설정 변경은 못 한다. 개발자 도구 없이 적용 설정·버전을 볼 수 있다 |
| TE-02 | 기준 설정·승인 | 차량/장비·출처·수식·단위·기준·반올림·승인 상태를 확인한다. 누락·미승인 설정은 판정 불가이며 연구 평가 시작이 차단된다 |
| TE-03 | 수행 중 설정 고정 | 교사가 새 설정을 배포해도 진행 중 수행은 시작 때 고정한 sessionSnapshotId와 versions를 유지한다. sessionConfigVersion·researchProtocolVersion·feedbackPolicyVersion을 포함한 바뀐 설정은 새 수행부터 적용된다 |
| TE-04 | 접수 상태 확인 | 학생의 실습 통과, 로컬 저장, 서버 접수 여부를 각각 확인한다. 미접수·거절·충돌을 해결할 안내가 있다. 학생 공개 API로 학급 전체 자료를 조회하지 않는다 |
| TE-05 | 취합·CSV 운영 | 교사 소유 비공개 Sheet에서 접수번호와 정본을 확인하고 CSV를 ID 기준으로 합친다. 재전송·CSV 병합 후 중복 성과가 늘지 않는다 |
| TE-06 | 공용 PC 인계 | 다음 학생 시작·미완료 복원·미접수 보존·수업 종료 정리를 교사용 안내만으로 수행한다. 로컬 자료 삭제는 확인된 운영/IRB 방침을 따른다 |
| TE-07 | 실제 배치 검토 | 외곽·고정장비·출입구·이동/안전 구역의 실측/사진과 가상 배치를 대조한다. 검토 전 layoutConfirmed는 false이며 실제 재현 완료라고 표시하지 않는다 |
| TE-08 | 교사 기능 접근 | 학생의 공개 접수 경로에 설정 변경·전체조회·일괄 내보내기를 포함하지 않는다. 메뉴를 숨기는 것만을 보안 통제로 주장하지 않는다 |

## 5. 연구·기록 요구사항

| ID | 요구사항 | 관찰 가능한 수용 기준 |
|---|---|---|
| RE-01 | 필수 연구 필드 | schemaVersion, recordId, anonymousStudentCode, classConditionCode, sessionCode, taskId, difficultyMode, startedAt, completedAt, durationSeconds, stepEvents, errorCount/errorTypes, safetyViolationCount/safetyViolationTypes, hintCount, measurementInputs, judgmentAnswers/judgmentCorrect, npcInspectionResult, retryCount, clientAppVersion가 [04](04_TASK_AND_LOG_SCHEMA.md)의 타입·누락 규칙에 맞는다 |
| RE-02 | 학습·전송 재시도 분리 | 새 수행은 새 recordId와 retryOfRecordId/retryCount 관계를 가진다. 같은 수행 재검사는 npcInspectionCount, 전송 재시도는 uploadAttemptCount에만 반영된다 |
| RE-03 | 첫 답·최종 답 분리 | judgmentCorrect는 최초 판정 정오 또는 null이다. measurementInputs·calculationAnswers·judgmentAnswers의 첫/최종 답·정오, 판독·계산의 단위를 보존하여 보완 통과가 최초 정오를 바꾸지 않는다 |
| RE-04 | 요약·이벤트 구분 | 분석용 요약과 stepEvents를 구분한다. feedbackShown은 feedbackKind:safety/explanatory/hint/guidance·feedbackKey·해당 시 itemId와 시점을 보존한다. 모든 키·좌표경로·화면녹화를 기본 수집하지 않는다 |
| RE-05 | 오류 집계 | 중복 actionId를 제거한 비안전 오류만 errorCount, 안전 오류는 safetyViolationCount에 집계한다. 네트워크·설정 오류가 학생 학습오류로 더해지지 않는다 |
| RE-06 | 시간 정의 | durationSeconds는 보이는 활성 학습시간의 누적 단조시간이며 업로드·숨김·새로고침 downtime은 제외한다. 단말 UTC startedAt/completedAt의 한계와 복원·일시중지·시간품질을 함께 기록한다 |
| RE-07 | 버전 재현 | 시작 때 sessionSnapshotId와 versions.sessionConfigVersion/researchProtocolVersion/feedbackPolicyVersion 및 과제·기준·측정세트·배치·판정엔진 버전을 고정한다. 연구 내용과 지원 정책을 재현하며 원본 설정을 덮어쓰지 않는다 |
| RE-08 | 연구 허용·대표 수행 | configurationApproval.researchUseApproved는 연구자의 사용 허용 상태이며 IRB를 대체하지 않는다. 허용되지 않은 설정으로 연구용 수행을 시작하거나 researchEligible:true로 만들지 않는다. primary나 접수 성공만으로 분석 포함·대표 수행을 자동 선정하지 않는다 |
| RE-09 | 연구 조건 구분 | classConditionCode·sessionCode의 의미와 발급 범위를 정의한다. 학급 번호·실험조건·동일 학생의 장기 연결을 코드만으로 추측하지 않는다 |
| RE-10 | 배치·모드 혼입 구분 | layoutConfirmed·배치 버전, 시작 displayMode·experiencedDisplayModes, 전환 이벤트의 fromDisplayMode/toDisplayMode·시점·이유를 남긴다. 평면 모드 수행을 3D 공간학습 성과에 무조건 합산하지 않는다 |
| RE-11 | 지표 분모 고정 | 과제 버전의 필수 판독·계산·판정 itemId를 중복 제거한 합집합으로 최초/최종 정답률 분모를 고정한다. 미응답 수를 함께 표시하고 채점 불가 설정은 null이다. judgmentCorrect와 전체 항목 정답률을 혼동하지 않는다 |

저장·제출 필드 `localSaveStatus`, `uploadStatus`, `uploadedAt`, `receiptId`는 `deliveryEnvelope`에 두고 CSV와 교사 취합 시 연구 내용과 함께 연결한다. 확정 `recordPayload` 해시에 전송 시도 횟수나 접수 시각을 섞지 않는다.

## 8. MVP 인수 전 필수 확인

1. 교사: 실측 치수·연결부·학생 시작점 확정과 상대 배치 초안 검토(사진·스케치는 2026-10-20 확보), 시험기/차량, 조작 순서·안전 절차, 수식·단위·기준·정밀도·절사 적용 범위 승인.
2. 연구자: 안내/무안내·최초/최종 답·대표 수행·힌트·결측·배점·IRB 계약 승인. 연구문제 수가 연구계획서 3개와 thesis CLAUDE의 2개 이하 원칙 사이에 충돌하므로 별도 결정.
3. 구현 검증: 학교 기기에서 키보드/터치, 오프라인·새로고침·저장실패·응답유실·동시 제출·학생 전환을 재현하고 기록·접수번호를 확인.
4. 범위 확인: 멀티플레이·ZEP·3인 역할·HMD·실시간 물리 차량·LLM NPC·다중 정비 과제·시간제한 평가는 MVP에 넣지 않음.
