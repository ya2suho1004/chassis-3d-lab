## 1. 공간 재현의 기준

사용자는 **실제 학교 실습장 배치를 최대한 재현**하기로 결정했다. 2026-10-20 기준 번호 사진 44장(`../../assets/photos/`)과 손 스케치 1장(`../../assets/hand-sketch.jpg`)이 있고, 장비별 상대 위치는 `../../review/layout-review.txt`와 `../../evidence/layout-review.json`에 정리됐다. 실측 치수는 없으므로 모눈 한 칸을 미터로 환산하거나 사진 원근으로 좌표를 확정하지 않는다. 상대 배치 초안(임시 개념 배치로 표시)을 교사가 검토한 뒤, 실측값으로 좌표를 채우고 3D에 적용한다.

재현의 우선순위는 ① 외곽·출입구·기둥·주요 구역, ② 고정 장비의 위치·방향·점유 공간, ③ 실제 제동력 작업 동선, ④ 장비 식별에 필요한 외형, ⑤ 장식·표면 질감 순이다. 낮은 성능에서는 외형 상세도·그림자·구역 로딩을 조절하고, 실제 장비 위치를 임의로 옮기지 않는다. 공간이 커도 MVP의 작동 과제는 제동력 하나다.

현실환경을 촬영하고 크기를 측정해 가상공간에 반영하는 근거는 한형종(2019) 인쇄 p.296/PDF311의 지침3.1에서 확인했다. 이 지침이 모든 물체의 사진처럼 사실적인 모델링을 의무화하거나 학교에서의 학습효과를 보장하는 것은 아니다. [설계원리 대응표](07_DESIGN_PRINCIPLE_TRACEABILITY.md)를 참고한다.

## 2. 교사가 준비할 최소 조사 묶음

처음부터 CAD 도면이나 전문 촬영이 필요하지는 않다. 아래 표의 ‘상태’ 열은 2026-10-20 기준이다. 손그림·공간 사진·장비 사진은 확보됐고, 축척 기준·안전 동선·조작 설명은 남아 있다.

## 3. 배치 데이터·검토 절차

1. 사진·스케치·측정값을 원자료 묶음으로 보관하고 서로 대응시킨다.
2. [layout.unapproved.json](../examples/layout.unapproved.json)의 `null`을 측정된 값으로 채운다. 단위는 m이며 좌표 기준과 장비 회전 방향을 설명한다.
3. 실측 후보값을 담은 비공개 검토 초안(`sourceStatus=surveyed`, `layoutConfirmed=false`)의 평면 도식에서 외곽·장비·출입구를 표시하고 교사가 실제 공간과 비교한다. 승인 전 공개 세션의 배치값은 null로 유지한다.
4. 최소 도형 3D 모델로 같은 배치를 재현하고 실제 핵심 동선을 따라간다.
5. 교사 확인일·검토 범위·미확인 구역·배치 버전을 남긴 뒤 `layoutConfirmed=true`로 공개한다.

일부 미조사 구역은 확인된 것처럼 채우지 않는다. 교사가 허용한 부분 재현이면 제외 구역과 학습목표에 미치는 영향을 명시하고 새로운 배치 버전에 반영한다. 현재 사용자 요구를 임의로 ‘작은 가상 방’으로 바꾸지 않는다. 개발용 임시 공간은 실제 학교 배치와 별도 버전으로 표시하고 연구용 공간학습 평가에 쓰지 않는다.

## 4. MVP 에셋 목록

에셋은 3D 모델·텍스처·아이콘·소리처럼 화면을 구성하는 자료다. 초기에는 직접 만든 단순 도형을 우선하며, 장비 식별과 교육적 동작에 필요한 만큼만 상세하게 만든다.

| 에셋 | 용도 | 우선 제작 방식 | 현재 상태 |
|---|---|---|---|

외부 무료 에셋 사이트나 ‘무료’ 표시만으로 사용 허가를 확정하지 않는다. 이 설계 단계에서는 외부 모델을 선택하거나 다운로드하지 않았으므로 **라이선스 확인 완료된 외부 에셋은 없다**.

## 5. 라이선스 확인표

외부 에셋마다 아래 필드를 채운다. 동일 사이트의 다른 모델도 개별 조건을 확인한다.

| 필드 | 확인할 내용 |
|---|---|
| `assetId`, 사용 파일 | 실제 배포 파일과 용도 |
| 원 URL·제작자·확인일 | 내려받은 항목의 출처 |
| 라이선스명·버전·원문 | 사용·수정·웹 포함·재배포 가능 범위 |
| 표시 의무 | 제작자·링크·변경내역 등의 정확한 요구 |
| 제한 | 교육 외 사용, 파생물, 상표·초상·제3자 권리 등 |
| 수정 여부·파일 해시 | 원본과 변환본 식별 |
| 용량·삼각형·텍스처 | [성능 예산](03_TECH_ARCHITECTURE.md)과 비교 |
| 승인 상태 | `pending` / `approved` / `excluded` 및 사유 |

직접 제작 모델도 참조 사진의 취득·사용 범위, 제작자와 수정일을 기록한다. 라이브러리·폰트·외부 아이콘의 의무는 모델과 별도로 관리한다. 최종 배포에는 필요한 `THIRD_PARTY_NOTICES`와 크레딧 화면을 제공한다. 확인되지 않은 항목은 실제 학생용 빌드에 포함하지 않는다.

## 6. NCS·기존 교과서 자료의 사용

- NCS 학습모듈의 그림·사진·표 이미지는 결과물에 그대로 넣지 않는다. 저작권자 표기가 있어도 그림 속 제3자 저작물까지 배포 허가가 확인된 것으로 간주하지 않는다.
- 승인된 작업 절차·용어·기록 항목을 참고해 자체 문장·도형·입력 UI로 재구성하고 모듈 코드·판본·인쇄 쪽을 적는다. 표3-1의 스캔이나 외형 복제 대신 과제에 필요한 입력 의미를 자체 화면으로 설계한다.
- NCS의 기준 숫자와 기존 코드의 ‘법정 고정값’이라는 주석은 현재 적용 기준의 검증을 대신하지 않는다. 학교 차량·시험기와 교사가 확인한 기준을 사용한다.
- 기존 `tasks.json`·`forms.json`·`judge.js`는 읽기 전용 원천이다. 기존 프로젝트를 수정하거나 논문 폴더에 새 파일을 만들지 않는다. 재사용할 필드·문구의 출처와 변환 내용을 기록한다.
- 원문 PDF·학교 사진·학생 연구자료를 공개 저장소나 배포 폴더에 넣지 않는다. 이번 산출물에도 원문 PDF와 원본 소스 전체 사본을 포함하지 않는다.

이 절은 프로젝트의 사용 원칙과 검토표이며 법적 허가 판정서가 아니다. 권리관계가 모호한 에셋은 직접 도형으로 대체하거나 권리자의 확인 후 사용한다.

## 7. 배치·에셋 인수 기준

교사는 실제 위치·방향·동선이 맞는지, 학생은 핵심 장비를 구분할 수 있는지 확인한다. 개발자는 스케일·충돌영역·접근점·저사양 성능·라이선스 표를 확인한다. 벽을 통과해 안전 순서를 건너뛰거나 장비가 겹쳐 조작을 가리는 경우는 수정 대상이다.

완료 조건은 ‘보기 좋은 실습장’이라는 표현 대신 **실측 근거→배치 데이터→교사 검토→버전 고정→실제 기기 동선 시험**의 증거로 판단한다. 상세도보다 배치 정확성·판독성·수업 지속성을 우선하되, 사용자가 확정한 실제 학교 재현 목표를 유지한다.
