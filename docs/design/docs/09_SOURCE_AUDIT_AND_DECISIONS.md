## 4. 기존 소스의 확인된 문제와 설계 반영

다음은 기존 함수의 직접 호출 결과와 소스 위치다. **진단용 입력이며 학교 차량 사례나 교사 승인 학습 데이터가 아니다.** 기존 UI에서 같은 입력을 막는지는 이번에 실행하지 않았다.

| 확인 위치 | 관찰한 문제 | 설계 반영 |
|---|---|---|
| `judge.js:13~16` | 공백이 0으로, Infinity가 숫자로 해석됨 | 입력 문법·유한수 검사 |
| `judge.js:91~96` | `judgeFixedRange(999,{})`가 pass | 빈 규칙을 설정오류로 거절 |
| `judge.js:107` | compute 누락 시 8/20/50 대입 | 숨은 기준값 폐기, 승인 규칙만 사용 |
| `judge.js:103~119` | 음수 좌·우·축중 조합도 pass 가능 | 좌우≥0·축중>0·단위 검사 |
| `judge.js:115` | 알 수 없는 position이 뒤축으로 처리됨 | front/rear enum을 필수 검증 |
| `judge.js:107~119` | 빈 rule도 ready:true와 fail | 설정오류·차량불량·학생오답 분리 |
| `judge.js:113~124` | 편차 원값8.004를 화면8로 반환하면서 fail | 표시·판정 자릿수 정책과 비교 근거 설명 |
| `tasks.json:2484/2490/2496` | 좌우 입력 단위 빈 문자열, 축중 kgf | 제시값·학생답·기준의 단위 명시 |
| `tasks.json:2468~2473` | 제동 과제 단계가 다섯 요약 문자열 | 실제 준비·조작·정지·안전조건과 단계 객체로 변환 |
| `tasks.json:2507~2515` | 규칙 상수와 ‘규정값 미설정’ 안내가 공존 | 승인·미승인 상태와 학생 안내를 동일 계약으로 정리 |

NCS p.98의 일반 합50% 문장과 p.99의 앞/뒤 조건, 압력 ‘7~10kg/㎠ 이상’ 표현은 교사 확인 대상이다. 현행 법령이나 학교 장비의 적용값을 이번에 확인한 것이 아니므로 정답 기준으로 바로 넣지 않는다.

기준·배치·연구사용이 미승인인 현재 예시는 `runPurpose=demo`, `researchEligible=false`다. 승인 플래그만 바꾸어 원문·현장·연구 절차를 대체하면 안 된다.

## 7. MVP 위험과 대응

실제 공간 재현은 자료 수집과 검토가 늦어지면 개발 일정의 병목이 된다. 조사와 저장·접수 기술검증을 병행하되 학교 좌표를 추측해 메우지 않는다. 외형을 세밀하게 만들기 전 배치 정확성과 핵심 동선을 확인한다.

Google/Cloudflare의 계정 정책·쿼터·학교망·공개 엔드포인트 오입력은 실제 시험이 필요하다. 제출 구현 전 같은ID 응답유실·동시요청·hash충돌·운영/preview 분리 시험을 통과시킨다. 정적앱의 점수는 신뢰된 시험서버가 보증한 성적이 아니며, 학생 코드도 신원 인증 수단이 아니다.

공용 기기 저장소는 영구 백업도 학생 간 강한 격리도 아니다. 접수번호 확인·미접수 현재기록 CSV·기기관리·보관/삭제 절차를 함께 운영한다. 비정상 종료 전 저장되지 않은 입력은 복구할 수 있다고 보장하지 않는다.

연구에서는 앱 로그와 외부 사전/사후 검사·면담의 역할을 나눈다. 비교학급 앱 로그 부재를 0으로 보정하지 않고, 가상공간 효과·절차 학습·판독 성과를 구분한다. 도식모드 이용과 피드백 노출이 섞인 결과를 모두 ‘순수 3D 무안내 수행’이라고 부르지 않는다.
