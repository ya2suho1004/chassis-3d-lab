## 2. 결정

| ID | 결정 | 사용자 확정 |
|---|---|---|
| D1 | 호스팅·저장: 화면은 Vercel, 수신·저장·서버 함수는 Supabase(Edge Function + Postgres, 서울 리전). Apps Script/Sheet, Cloudflare Pages, GitHub Pages 경로는 쓰지 않는다. 학교 Wi-Fi에서 `vercel.com` 관리 화면은 차단되지만 `프로젝트.vercel.app` 하위 주소와 배포 API는 열림을 확인했다(2026-10-28, 영향분석 C11). Vercel 계정 생성·설정은 학교 밖에서 한다 | 10-28 |
| D2 | 기록 계약(IndexedDB 선저장, recordId 중복 방지, 서버 접수번호, 재전송, CSV 비상 백업, JCS→SHA-256 대조)은 그대로 두고 수신처만 Supabase로 옮긴다. 표에는 RLS를 켜고, 학생 화면은 다른 학생 기록·연구결과를 조회할 수 없다. 비밀 키는 서버 함수에만 둔다 | 10-28 |
| D3 | AI 교관 챗봇 추가. 대본형 NPC(과제 안내·검사·보완/통과 판정)는 유지하고 챗봇은 질의응답 보조로 분리한다. 판정·채점은 챗봇이 하지 않는다. 답변 범위는 제동장치 점검·제동력 측정·장비 사용·안전수칙. 무안내 단계에서는 측정값·판정 정답을 직접 말하지 않고 힌트·되묻기로 안내한다. 교사가 켜고 끄며, 교사만 대화 기록을 본다. 대화 기록을 연구 자료로 저장한다 | 10-28 |
| D4 | 수업은 5차시 모형(1~2차시 시뮬레이션, 3~4차시 실제 실습, 5차시 시뮬레이션 정리). `usagePhase` 값은 그대로 두고 뜻만 재정의한다: **preview = 실제 실습 전 시뮬레이션(1~2차시), review = 실제 실습 후 시뮬레이션(5차시), other = 그 밖의 보조 사용(3~4차시 등).** record 1.1.0 계약 변경 없음. 시작 화면 문구는 구현 때 바꾼다 | 10-28 (영향분석 C2 추천 A) |
| D5 | 3D 품질 향상을 최우선 과제 중 하나로 둔다. 설계 08 §1의 재현 우선순위에서 "장비 식별에 필요한 외형"과 "표면 질감"을 올리되, 실측 전 배치는 계속 임시 배치로 표시한다 | 10-28 (지도교수 지적) |
| D6 | Apps Script 수신점은 삭제하지 않고 `archive/apps-script/`로 보관한다. 새 서버가 같은 규칙을 지키는지 확인하는 기준 구현과 시험으로 쓴다 | 10-28 |
| D7 | 챗봇 모델: 개발·시연 단계는 Google Gemini 무료 API로 시험하고, 학생 적용 전에 유료 모델(Anthropic 또는 OpenAI)로 바꾼다. 서버 함수에 모델 교체 지점을 하나만 둔다. 조건: Gemini 약관상 18세 미만 대상 앱 사용이 금지되므로 Gemini는 성인(교사·교수·연구자)만 쓰는 개발·시연에 한정한다. 무료 등급 입력은 구글이 학습·사람 검토에 쓸 수 있으므로 합성 질문·가짜 데이터만 넣는다 | 10-28 |
| D8 | 시연 버전(11-10 배포 URL)은 가짜 코드·가짜 데이터만 쓴다. 실제 학생 적용은 IRB 승인 후(12월 기말고사 이후) | 10-28 |
