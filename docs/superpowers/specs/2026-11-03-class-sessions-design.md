# 실제 수업 세션 연결 설계 (2026-11-03, 사용자 승인)

## 목적
- 지금까지 학생 화면은 시연 세션(DEMO-ONLY)에만 기록했다. 12월 실제 적용 전에 교사가 기기마다 '오늘 세션'을 골라 기록과 AI 교관 질문이 그 세션으로 가게 한다.
- 연구 세션은 IRB 승인 전에는 잠가 둔다. 같은 흐름을 가상 코드로 미리 돌려 보는 리허설 세션을 둔다.

## 결정(사용자 2026-11-03)
- **세션 구성:** 차시별 3개(실험 학급 1~2차시 · 5차시 · 사용성 평가)로 나눈다. 비교 학급은 시뮬레이션을 쓰지 않으므로 세션이 없다.
- **익명 코드 형식:** 나중에 정한다(IRB·동료 교사와 정한 뒤). 세션마다 설정값(`anonymousCodePattern`)으로 넣는다.

## 동작
- **교사 화면 ① 수업 전 '오늘 세션':**
  - 세션이 정한 차시·도움 방식은 고정한다(학생 화면에서도 바꿀 수 없음).
  - 연구 세션은 고를 수 없다.
- **학생 화면:** 교사가 고른 세션으로 `createDemoSession`을 만든다(스냅샷 대조). 기록·AI 질문의 `sessionCode`가 그 세션이다. 모양은 그대로다.
- **스냅샷:**
  - 생성기가 시연·리허설 세션만 만든다. 리허설은 runPurpose=demo이고 승인 표시는 시연과 같다.
  - 원장은 덧붙이기만 한다. 기존 72개는 바뀌지 않고 리허설 48개만 더해 120개가 된다.
  - 서버 허용 목록은 121개(fixture 포함)이고, 모두 가상 코드 `^D-[0-9]{2}$`만 받는다.
- **AI 세션 표:** 마이그레이션 `20261103120000_rehearsal_sessions.sql`로 REH-L12·REH-L5·REH-USAB를 챗봇 꺼짐으로 만든다. 교사가 ② 수업 중에서 켠다.
- **서버 반영(“재배포해” 때):**
  - `supabase db push`(마이그레이션)
  - `supabase functions deploy submit`(허용 목록 갱신)
  - Vercel(화면)

## 연구 세션 열기 절차(IRB 승인 뒤 — 그때 사용자 확인을 받고 진행)
1. **승인 확인:** IRB 승인 번호·승인일, 과제 승인, 실습장 배치 확정(실측), 익명 코드 형식(동료 교사와 정함).
2. **연구 세션 스냅샷 만들기:** 생성기에 연구 세션용 블록을 더한다.
   - `runPurpose: 'research'`
   - 승인 4종 true
   - `researchProtocolVersion`: IRB 번호를 담은 값
   - `anonymousCodePattern`: 정한 형식
   - 원장 덧붙이기다. 기존 시연·리허설 스냅샷은 그대로 둔다.
3. **잠금 풀기:** `sessions.json`의 해당 세션 `pending: false`.
4. **서버 반영:**
   - 연구 세션 행 마이그레이션(챗봇 꺼짐)
   - `supabase db push`
   - submit·chat 함수 배포
   - Vercel 배포
5. **확인:**
   - 리허설과 같은 시험을 연구 세션으로 돌린다.
   - 가상 코드로 서버 접수를 확인하되 실제 학생 자료는 넣지 않는다. 시험 기록은 분석에서 빼도록 표시한다.
6. **IRB 원고와 맞추기:** 수집 항목의 '수업 세션/연구조건 코드'가 위 표와 같은지 확인한다.
