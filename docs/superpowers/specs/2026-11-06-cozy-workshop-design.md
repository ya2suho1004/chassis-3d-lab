# 따뜻한 정비 공방 — 화면 분위기·재미 요소 설계 (2026. 11. 6.)

> 상태: **방향 승인**(MOON 2026-11-06, 분위기 A안·(다) 완성 모습). 구현은 이 문서 검토·승인 뒤, **11-10 시연 이후**. 11-08 코드 고정 전에는 손대지 않는다.
> 근거: MOON 요청("마비노기 모바일을 미적으로·운영 방식으로 지향, 무엇보다 재미"), Codex 토의 2회(`docs/CODEX_디자인재미_토의요청_2026-11-06.md`, 원문 `docs/CODEX_디자인재미_토의결과_2026-11-06.md`), 시안(브레인스토밍 화면 mood-direction·package-da-A, 로컬 전용).

## 1. 목표와 범위

**목표:** 지금의 "업무용 웹 화면 + 3D 실습장"을 **"따뜻한 학교 정비 공방에서, 내가 살펴보고 판단해 손님 의뢰를 마치고, 그 흔적이 수첩에 쌓이는 경험"**으로 바꾼다.

- 재미의 중심은 점수판이 아니라 **"관찰 → 판단 → 의뢰 완료"의 손맛과 쌓이는 흔적**이다.
- 지향하는 게임에서 가져오는 것은 **느낌을 만드는 원리**뿐이다: 따뜻한 빛, 둥근 형태, 부드러운 그림자, 조작에 대한 반응, 모으기와 의뢰가 쌓이는 운영 방식. 그 게임의 그림·캐릭터·로고·아이콘·UI 모양·음악·이름·세계관 용어는 쓰지 않고, 모두 새로 만든다.

**단계:**
| 단계 | 내용 | 작업량(1인 추정) |
|---|---|---|
| 1단계 = 패키지 (나) | (가) 분위기 통일 + 손맛 + 의뢰 마무리 | 5~7일 |
| 2단계 = 패키지 (다) | 정비 수첩 + 숨은 것 찾기 + 오늘의 의뢰판 | +5~8일(합계 10~15일) |

1단계만으로도 완결된 판이 되게 한다(2단계는 연구 일정·IRB 확인 뒤 결정).

**비목표:** 캐릭터 비율·뼈대 전면 수정, 새 과제·새 사례 수치, 배경음 제작, 사진 촬영·공유, 친구·온라인 기능, 누적 등급 체계.

## 2. 지키는 규칙

1. **두 겹 색 규칙:** UI 패널·간판·인트로·대화창은 따뜻하고 채도 있게 만든다. **계측부는 원래 색을 유지한다.** 계측부란 3D 눈금판·바늘·계기 표시창·안전 표시·측정/계산/판정 입력 칸·결과의 측정→계산→판정 칸이다. 계측부는 따뜻한 색 보정, 반짝임, 화면 효과에서 뺀다. 주황 강조색은 안전 경고와 모양·문구로 구분한다.
2. **판정·채점·기록 형식은 바꾸지 않는다:** 승인된 계산식·절사·안전 조건·최초 응답 피드백 정책, `record.schema`, 같은 recordId 재전송, `researchEligible=false`, 연구 세션 잠금을 그대로 둔다.
3. **안내 없음:** 다음 단계에 따라 장비 빛·카메라·교관 시선·효과음을 바꾸지 않는다(A1과 같은 원칙). 반응은 "눌렸다"까지만 하고, 정답 여부는 기존에 허용된 시점에만 알린다.
4. **넣지 않는 것:** 순위표, 속도·연속 정답 보상, 힌트를 안 쓰면 주는 보상, 오답 벌점, 무작위 뽑기, 출석 보상, 실시간 채팅·멀티플레이. 도장·꾸미기의 조건에 시간·힌트·오답·재시도를 쓰지 않는다.
5. **학교 태블릿:** 품질 낮음에서도 색·패널·반응의 인상이 같아야 한다. 빛줄기·그늘 같은 장식만 품질 높음 전용으로 둔다. 새 글꼴·음악 파일은 내려받지 않는다(시스템 글꼴, 합성 효과음).
6. **연출이 수행을 막지 않는다:** 연출이 끝나야만 다음 조작이 되는 구조는 만들지 않는다. 긴 필수 연출도 넣지 않는다. 움직임 줄이기 설정(`prefers-reduced-motion`)에서는 연출을 정지 표시로 바꾼다.

## 3. 디자인 체계 (A안: 따뜻한 정비 공방)

**색 토큰**(`src/styles.css` `:root`에 이름으로 둠, 시안 값):
| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `--wa-cream` | `#fff6e5` | 패널 바탕 |
| `--wa-paper` | `#fffaf0` | 카드·입력 영역 바탕 |
| `--wa-line` | `#c98b4f` | 테두리·패널 아래 그림자(2~3px 단색) |
| `--wa-brown` | `#8b5e34` | 제목 띠(게시판 머리) |
| `--wa-ink` | `#5b3a1e` | 패널 글자 |
| `--wa-orange` / `--wa-orange-d` | `#f28c28` / `#b45f12` | 주 행동 버튼 / 버튼 아래 그림자 |
| `--wa-navy` | `#26364a` | 알림 띠·실습복과 연결 |
| `--wa-stamp` | `#d2463a` | 도장 |
| 배경 노을 | `#ffe0b2 → #ffcf96 → #f6b27a` | 시작·캐릭터·결과 화면 바탕 |

- **패널:** 둥근 모서리 16px, 테두리 2px, 아래로 3px 단색 그림자. 큰 반투명 흐림 효과(backdrop-filter)는 줄인다(태블릿 부담).
- **버튼:** 주 행동은 주황 알약 모양 한 가지만, 나머지는 크림 바탕에 갈색 테두리를 쓴다. 눌림은 2px 내려가는 반응으로 보인다.
- **글자:** 시스템 글꼴을 유지한다. 제목은 굵기와 여백으로 개성을 낸다. 숫자는 자릿수가 고른 숫자(`font-variant-numeric: tabular-nums`)로 쓴다. 장식체와 작은 글자는 쓰지 않는다.
- **아이콘·도장 그림:** 직접 그린 작은 SVG(공구·차·계기·고양이 등)를 쓴다. 이모지에 기대지 않는다(태블릿 글꼴마다 다르게 보임).
- **교사 화면:** 색·글꼴·버튼만 함께 쓰고, 표·입력칸 중심의 명료한 구성은 그대로 둔다.

**3D 쪽(1단계):**
- 조명에 약한 온기를 더한다. 단, 측정판·계기 주변은 중립 흰빛을 유지한다(계측부 규칙).
- 차량·바닥의 반사를 조금 줄이고 실습복은 무광으로 한다. 금속·고무 구분은 유지한다.
- 창으로 드는 햇살 빛줄기는 품질 높음 전용으로 둔다.
- 통로 밖에 생활 흔적(공구 정리판·닫힌 부품함·작은 휴식 코너)을 몇 개 둔다. 누를 수 있는 대상은 늘리지 않는다. 숨은 것 찾기 대상(2단계)만 예외로 한다.

## 5. 손맛 (1단계)

반응을 두 층으로 나눈다.
- **접수 반응**(모든 모드): 버튼 눌림, 장비가 실제로 움직임, 짧은 합성음. 손을 떼면 조작이 바로 멈추고, 조작 전·후 상태가 분명히 바뀌며, 확대에서 돌아올 때 원래 시점으로 자연스럽게 돌아온다.
- **완료 연출**(기존에 완료·통과를 알려 주는 시점에만):

| 연출 | 시점 | 조건 |
|---|---|---|
| 보호구 착용 반짝임 | 기존 착용 처리 뒤 | 착용 모습이 먼저 보이고, 눈금·시야를 가리지 않음 |
| 측정판 끝 '딸깍' | 핸들이 **조작 한계**에 닿을 때 | 정답 각도 도달 신호가 아님 |
| 교관 엄지 몸짓 | NPC 검사 통과 뒤 | 대사 추가·대기 없음 |
| '의뢰 완료' 도장 + 종이 조각 | 결과 화면 | 태블릿은 2D 조각 몇 개, 움직임 줄이기면 정지 도장 |

- 소리는 지금처럼 **기본 꺼짐**으로 두고, 켜면 합성음(`src/scene/sound.ts`)으로 낸다.
- 단계마다 찍던 큰 도장은 쓰지 않는다. 단계 완료는 작은 체크 반응으로 하고, 큰 도장은 의뢰 종료에만 쓴다.

## 6. 2단계 (다) 기능

### 6-1. 정비 수첩 (도장첩)
- **도장 4종:**
  - 의뢰: NPC 검사 통과, 사례별 1개
  - 장비 발견: 처음 살펴봄, 23개
  - 연습: 런아웃·백래시 연습의 기존 완료 조건 충족
  - 숨은 것: §6-2
- 같은 항목을 되풀이해도 도장은 하나다. 수첩을 채워야 열리는 것은 없다.
- **저장:** 이 기기에만 저장하고, 수업 세션 코드 + 익명 코드로 나눈다(공유 태블릿에서 반·학생이 섞이지 않게). 항목별로 `있음/없음`만 남기고 **시각·횟수·오답·힌트는 남기지 않는다.** 서버·`record.schema`·AI 요청에는 넣지 않는다.
- **기록 없이 하기:** 메모리에만 두고 화면을 나가면 사라진다.
- **지우기:** 교사 화면 ①에 "이 기기 정비 수첩 지우기"(세션별·전체)를 둔다. 단원이 끝나면 교사가 지운다. 결과 화면에서는 "새 도장 n개" 띠로 알리고, 과제 중에는 수첩을 띄우지 않는다.

### 6-2. 숨은 것 찾기
- 3개로 시작한다(예: 휴식 코너 고양이 인형 등). **학습 정보가 없는 장식 발견만** 넣는다. 정비 상식 포스터처럼 과제 순서·공식·판정을 알려 주는 것, 공구판 빈 자리처럼 과제로 오해할 수 있는 것은 넣지 않는다.
- 과제 수령 전(둘러보기)에만 반응한다. 과제 중에는 반응·알림을 끈다. 찾지 않아도 바로 과제를 받을 수 있다. 미발견 숫자로 재촉하지 않는다.

### 6-3. 오늘의 의뢰판
- 시작 화면의 게시판에서 의뢰 카드를 고르고 → 들어가서 → 교관에게 기존 방식으로 수령한다. 수행 중에는 의뢰를 바꾸지 않는다.
- 카드 내용은 **승인된 사례만**(지금 두 과제 × 사례 1·2) 쓴다. 손님 사연 문구는 기존 작업지시(`panelWorkOrder`)에서 가져오고, 새 문구는 교사 검토를 받는다. 사연이 판정(양호/불량)을 암시하면 안 된다.
- 교사 설정 확장: 지금 `TeacherPreset`은 사례 하나 + 잠금이다. 이것을 **열어 둔 사례 목록**으로 넓힌다. 잠금이면 카드 하나만 고를 수 있고, 연구 세션은 정해진 배정을 따른다. 자유 연습 세션에서만 여러 카드를 연다.
- 끝낸 의뢰 카드에는 '완료' 도장을 보인다(정비 수첩과 같은 저장소).

## 7. 연구·IRB

- 재미 요소도 중재(프로그램)의 일부다. **사용성 평가 전에 1단계 판을 확정**하고, 사용성 평가판과 현장 적용판이 달라지면 변경 내용과 시점을 연구 절차에 적는다.
- 2단계의 정비 수첩은 **새로 생기는 기기 안 이력**이다. "기기 안이면 IRB 영향 없음"으로 판단하지 않는다. Hermes에게 아래 설명을 IRB 원고에 넣을지, 이미 제출한 판이 있으면 변경 심의가 필요한지 확인을 요청한다.

  > 학습 참여를 돕기 위해 장비 도감, 의뢰·연습 완료 도장 및 캐릭터 꾸미기를 제공한다. 정비 수첩에는 수업 묶음과 익명 코드에 연결된 항목별 발견·완료 여부만 기기 내부에 저장하며, 시간·횟수·오답·힌트 사용 내역은 추가 저장하지 않는다. 해당 정보는 서버로 전송하거나 연구 분석 자료로 사용하지 않으며 성적에 반영하지 않는다. 비기록 모드에서는 영구 저장하지 않고, 저장된 수첩 정보는 단원 종료 시 삭제한다. 제공 범위와 시점은 연구 절차에 명시한다. (Codex 초안)

- 의뢰판으로 사례를 고르는 순서·반복이 자유로워지면 연습 노출량이 바뀐다. 연구 수업은 정해진 배정을 따르고, 자유 연습만 선택권을 준다.

## 8. 구현 단위 (계획 문서에서 쪼갬)

1. 디자인 토큰·공통 패널/버튼 컴포넌트 → 시작·캐릭터·결과·HUD·대화창 적용(1단계)
2. 결과 화면 '정비 일지' 배치(기존 `resultLabels` 재사용) + 의뢰 완료 도장(1단계)
3. 손맛: 반응 정책 함수(모드·시점별로 허용되는 반응) + 연출(1단계)
4. 3D 조명·재질 조정 + 생활 흔적 소품(1단계)
5. 정비 수첩 저장소(세션·코드 구분, 지우기) + 화면(2단계)
6. 숨은 것 3개(2단계)
7. 의뢰판 + 교사 설정 확장(2단계)

## 9. 시험·확인

- **단위 시험:**
  - 반응 정책: 안내 없음에서 다음 단계에 따라 바뀌는 빛·소리·시선이 없는지
  - 도장 조건: 시간·힌트·오답과 무관한지, 같은 항목은 도장 하나인지
  - 수첩 저장: 세션·코드가 섞이지 않는지, 지우기, 기록 없이 하기에서 저장되지 않는지
  - 의뢰판: 잠금이면 카드 하나, 연구 세션은 정해진 배정
  - `record.schema` 출력이 바뀌지 않는지(이전 판과 같은 입력이면 같은 payload)
- **화면 확인:** 헤드리스로 각 화면을 품질 높음·낮음에서 비교한다. 계측부 색은 이전 판과 픽셀로 비교한다(따뜻한 보정이 새지 않았는지).
- **실기기:** 학교 태블릿에서 판독(눈금·숫자), 터치, 화면 전환 시간, 처음 받는 자료 크기 증가(제안 목표: +300 KB 이하 — 실측 뒤 조정)를 본다.
