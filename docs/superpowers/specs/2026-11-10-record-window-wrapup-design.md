# 기록 창 마무리 묶음 설계 (2026. 11. 10., MOON 승인)

> 브랜치 `cozy-stage1`에서 구현한다. 공개판 반영은 MOON이 "재배포해"라고 할 때만.
> 근거: 기록 창 최종 검토(f098c4a 뒤)와 Codex 회의 남은 항목(`docs/CODEX_기록창_토의결과_2026-11-10.md` 0절 순서 4).
> MOON 결정(2026-11-10, "추천대로 해"): ① 채점 규칙 **가** ② 고친 값 경고 넣기 ③ 마지막 첫 답이 틀려도 고칠 목록 띄우기 ④ 결과 화면에서 정답 값 숨기기.

## 1. 목표와 하지 않는 것
- 계산 답 채점을 설계 계약대로 고친다(둘째 자리 이하에 0이 아닌 숫자가 있으면 오답).
- 학생이 고친 값을 '입력' 없이 두는 실수를 막는다.
- 안내 없음에서 고칠 목록이 늘 뜨게 한다.
- 끝난 화면에서 정답 값을 감춘다.
- 작은 흐름 문제 4건을 고친다.

**하지 않는 것:** 판정 엔진 판 번호 올리기(§2), 교사용 상세 기록(JSON) 감추기(§5), E2 AI 함수 배포, QR 입장.

## 2. 채점 규칙 — 가
- 계산 항목(편차·합·반경)은 학생 값을 다시 절사하지 않고 기준값과 그대로 비교한다. `6.69`·`6.6999`·`73.39`·`5.19`는 오답, `6.6`·`6.60`·`73.3`·`5.1`은 정답이다. 형식 오류가 아니라 채점된 오답이므로 첫 답으로 남는다.
- 계약 근거: `docs/design/contracts/task-vocabulary.v1.2.0.json` 296–302, 13번 문서 104줄("학생 답을 또 절사해 오답을 정답으로 바꾸지 않는다").
- 판독(정수)·판정 채점은 그대로다. 기준값 계산(차량 판정용 절사)도 그대로다.
- **판정 엔진 판 번호(`judgeEngineVersion` 0.1.0)는 올리지 않는다.** 시연 세션 스냅샷 120개·장부(`src/data/session/*.json`)와 서버 접수 코드에 고정돼 있어, 올리면 스냅샷 재생성과 서버 배포가 필요하다. 이번 변경은 코드를 계약에 맞추는 것이므로, 이전 판과는 앱 판(`clientAppVersion`의 커밋)으로 나눈다. 학생이 적은 글자(`firstInput`·`finalInput`)가 기록에 그대로 있어 이전 기록도 새 규칙으로 다시 채점할 수 있다(Hermes).
- 서버 접수는 답을 다시 채점하지 않고 형식만 본다(`receiverCore`의 `validateRecordSemantics_`). 접수가 막히지 않는다.

## 3. 고친 값 경고
- **칸 표시:** 칸 글자가 비어 있지 않고 제출한 최종 답(`restoreInputs`)과 다르면 그 칸 표시는 "입력 전"이다(정오 표시보다 먼저). 작업 목록·기본 화면·기록 창 모두 같다. 정오를 드러내지 않는다.
- **기록 창에서 닫기·단계 완료:** 그 단계 칸 중 이미 입력한 답을 고쳤지만 입력하지 않은 칸(고친 값)이 있으면 처음 한 번은 닫거나 끝내지 않고, 창 안에 "고친 값을 아직 입력하지 않았습니다 — ○○ 칸 옆 입력을 눌러야 저장됩니다. 그대로 두려면 한 번 더 누르세요."를 보인다("입력칸으로" 버튼 포함). 다시 누르면 그대로 진행한다. 칸에 적은 글자는 남는다(제출되지 않음).
- 처음 적고 아직 한 번도 입력하지 않은 칸은 경고 대상이 아니다(구현 중 보완, 2026-11-10). 칸 표시는 "입력 전"이고, 단계 완료를 누르면 지금처럼 "○○ 칸 옆 입력을 눌러야 저장됩니다"가 뜬다. 이 칸까지 경고하면 "한 번 더 누르세요" 뒤에도 단계가 끝나지 않아 안내가 틀리게 된다.
- 경고 여부는 창을 열 때·닫을 때·'입력'을 누를 때 처음으로 돌린다.
- 기록은 바뀌지 않는다(사건 없음).
- **검토·검증 반영(2026-11-10, 구현 뒤):**
  - 경고가 '다시 확인할 항목' 목록을 덮으면 경고에도 같은 고치기 버튼을 붙인다. ✕·Esc·닫기로 닫거나 고치기로 다른 창으로 옮기면 원래 목록으로 되돌린다. 단계 완료로 닫히면 지금처럼 비운다.
  - 창 안 '고치기'로 다른 단계 창으로 옮길 때도 같은 경고를 거친다.
  - 창 밖(큰 버튼·작업 목록 줄·기본 화면 단계 버튼)에서 기록 단계를 끝내려 할 때도, 그 단계에 고친 값이 입력 전이면 바로 끝내지 않고 한 번 알린다. 게임 화면은 그 단계 창을 열고 창 안에서 알린다. 다시 누르면 저장된 답으로 끝난다.

## 4. 고칠 목록 — 마지막 첫 답이 틀렸을 때
- 안내 없음에서 마지막 최초 답이 오답이면, 지금처럼 그 칸 설명을 보이면서 '다시 확인할 항목' 고치기 버튼(`fixItems`)도 함께 붙인다. 같은 `show()`·같은 피드백 키라 사건은 같다.

## 5. 결과 화면의 정답 값 숨기기
- 결과 화면 표에서 "제시/기준값" 칸(실제 판독값·계산 기준값·정답 판정)과 "차량 판정(정답)" 줄을 뺀다. 학생 답과 ✓·✗, 정답 수는 그대로 보인다. 화면에 "정답 값은 교사 화면에서 확인합니다"를 적는다.
- 한계: 같은 화면의 "교사용 상세 기록 보기"(JSON)·내려받기에는 값이 남는다. 교사 로그인 뒤로 옮기는 일은 따로(MOON·Hermes 판단).

## 6. 작은 흐름 수정
1. **검사 연결:** 의뢰 카드의 "교관에게"를 누르면 걸어간 뒤 교관 대화가 열린다(지금은 걷기만). 과제 중이면 대화에 "검사 받기"가 있다. 걷는 중에 다른 곳(장비 버튼 등)으로 가면 대화 예약은 취소된다(검토 반영). 조이스틱·바닥 누르기로 방향을 바꾼 경우는 남을 수 있다(교관 2 m 안에서 멈출 때만 열림).
2. **경고 제목:** 정지·상승·차량 빼기에서 순서 오류(`ORDER_*`)는 "순서가 틀렸습니다 — ○○", 안전 오류(`SAFETY_*`)는 "안전 위반 — ○○"로 나눈다(엔진 집계와 같게).
3. **교관 대사:** 과제를 받은 뒤 "작업 순서는 오른쪽 위에 보여"를 "작업 순서는 작업 목록에서 확인해"로(안내 없음과 맞게).
4. **"저장" 표시:** 작업 목록·기본 화면 칸의 표시 칸을 24px에서 36px로(두 줄로 쌓이지 않게). "입력 전"은 작은 글자로 한 줄. 검증 반영: 표 칸 안 표시도 줄바꿈하지 않는다(1280×800 작업 목록 표에서 '저/장'으로 쪼개졌음). 표시 칸은 36px 이상이고 글꼴이 넓으면 늘어난다.

## 7. 자료 영향 (Hermes 전달)
- 계산 답 정오가 바뀐다(§2). 이 커밋 이후 수행부터 새 규칙. 이전 기록은 적은 글자로 다시 채점 가능.
- 나머지(§3~6)는 화면만 바뀐다. 새 사건·항목 없음. 고칠 목록이 더 자주 뜨면 학생의 수정 행동이 늘 수 있다(이전 판과 나눠 분석).
- **검토 반영:**
  - **앱 판:** 기본 판을 `0.3.1-demo`로 올려 새 채점 규칙 기록을 가른다. 판정 엔진 판 0.1.0은 그대로다. 연구 묶음 설명서(README)에도 적는다.
  - **이어 하기:** 이어 하기로 이어진 수행은 처음 시작한 판이 남는다. 그래서 한 수행 안에 두 규칙이 섞일 수 있다.
  - **다시 채점의 한계:** 계산 정오는 적은 글자로 다시 채점할 수 있다. 하지만 `errorTypes`의 calc, `answerSubmitted`의 INCORRECT, `feedbackShown`, NPC 검사 결과는 다시 만들 수 없다.
  - **feedbackKind 변경:** 정지·상승·차량 빼기에서 순서 오류(`ORDER_*`)가 나면 `feedbackShown.feedbackKind`가 `safety`에서 `explanatory`로 바뀐다. 엔진 집계와 `doStep`에 맞춘 것이다(§6.2).

## 8. 확인 방법
- 자동 시험: 채점(6.69·6.60·73.39·5.19·5.10), 고친 값 판단·칸 표시(순수 함수), 창 닫기·단계 완료 경고 배선, 고칠 목록 배선, 결과 화면·대사·교관에게·제목 배선.
- 브라우저: 기록 창에서 값을 고치고 입력 없이 닫기·단계 완료(경고 → 두 번째에 진행), 안내 없음에서 마지막 첫 답 오답 시 목록, 결과 화면에 정답 값 없음, "교관에게"로 대화 열림.
