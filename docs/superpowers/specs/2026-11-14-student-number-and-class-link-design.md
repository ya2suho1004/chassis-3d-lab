# 학번 입장과 수업 주소 — 설계

- 날짜: 2026-11-14. 상태: 설계 확정(MOON 2026-11-14), 구현 끝(브랜치 `cozy-stage1`, 앱 판 0.3.7-demo, 합치기·배포 전). 교사 화면(PIN 뒤)의 주소·QR 모습은 MOON 확인 대기.
- 관련: 수업 세션 설계 `2026-11-03-class-sessions-design.md`, QR 입장 설계 `2026-11-09-qr-entry-design.md`(구현되지 않음. 이 문서는 그 가운데 "교사가 정한 수업을 학생 기기에 전달"만 서버 없이 푼다).

## 1. 목표
1. 학생이 익명 코드(`A-01`) 대신 학교에서 쓰는 학년반번호 네 자리(2학년 2반 11번 → `2211`)로 들어온다.
2. 과제 고르기는 교사만 한다. 학생 화면에는 고르기가 없고, 학번을 넣으면 바로 실습장으로 간다.

## 2. MOON 결정 (2026-11-14)
1. 학번은 **앱 화면만 먼저** 바꾼다. 서버는 지금처럼 수행 기록을 가상 코드(`D-01`~`D-99`)만 받는다. 학번으로 한 수행 기록은 기기에 남고 교사 화면에서 내려받는다. AI 교관에게 질문하면 서버 대화 기록에 학번이 남는다는 점을 알고 정했다.
2. 학번 형식은 학년(1~3) + 반(1~9) + 번호(01~99) 네 자리다. 서버 접수 시험용 가상 코드는 리허설 세션에서만 받는다.
3. 태블릿은 학생마다 한 대다. 그래서 교사의 수업 설정은 **주소(링크·QR)에 담아** 전달한다(지휘 세션 추천안. 태블릿마다 교사가 설정하는 방식은 대수가 많아 맞지 않는다).

## 3. 범위
### 들어가는 것
1. 입장 코드 규칙: 세션 종류(`sessions.json`의 `kind`)에 따라 다르다.
   - `rehearsal`: 가상 코드 `^D-\d{2}$`만(서버가 받는 범위와 같다).
   - 그 밖(`demo`, 그리고 아직 열리지 않은 `research`): 학번 `^[1-3][1-9](0[1-9]|[1-9]\d)$`.
   - 연구 세션의 코드 형식은 IRB와 함께 다시 정한다(지금은 고를 수 없는 세션이라 닿지 않는다).
2. 시작 화면: 안내·라벨·자리 표시·오류 글을 학번에 맞게 고치고 숫자 자판을 띄운다. "이름·학번·연락처는 넣지 않아요"는 "이름·연락처는 넣지 않아요"로 바꾼다. 리허설 세션에서는 가상 코드 안내를 보인다.
3. 학생 화면에서 과제·차시·도움 방식 고르기를 없앤다. "오늘 과제" 한 줄(과제 · 차시 · 도움 방식)만 보인다. 교사 설정이 없는 기기는 지금의 기본값(시작 화면의 처음 선택값)으로 들어간다.
4. 수업 주소: 교사 화면 ① 수업 전에서 설정을 저장하면 그 설정이 담긴 학생용 주소와 QR을 보여 준다(주소 복사 버튼). 학생 기기가 그 주소로 열리면 설정을 기기에 저장하고 주소의 `#` 값을 지운다.
   - 설정은 주소의 `#` 뒤에 둔다(서버 요청에 실리지 않는다). 개인 정보는 담지 않는다(세션·과제 사례·차시·도움 방식·차량 진입 방향뿐).
   - 읽을 때 `parsePreset`과 같은 검사를 거친다. 알 수 없는 값·잠긴 세션·판이 다른 주소는 적용하지 않고, 시작 화면에 "수업 주소를 읽지 못했어요. 선생님께 알려 주세요"를 보인다(이전 설정은 그대로).
   - 전체 주소가 QR 한도(106자) 안에 들도록 짧게 적는다.
5. QR 생성: 새 패키지 없이 `src/teacher/qr.ts`(버전 1~6, 오류 정정 M, 바이트 방식). 2026-11-09 계획 문서(`docs/superpowers/plans/2026-11-09-qr-entry.md`)의 Task 2 코드와 시험을 바탕으로 한다.
6. 교사 화면 글: "학생이 바꾸지 못하게" 체크는 없앤다(늘 막힘). "익명 코드·가명 코드"라고 적힌 글을 사실에 맞게 고친다 — 학번은 학생을 알아볼 수 있는 값이라는 점, 서버는 리허설 세션의 가상 코드만 받는다는 점, 학번 기록은 기기에서 내려받는다는 점.
7. 앱 판 0.3.7-demo. 연구 자료 묶음 설명서의 `anonymousStudentCode` 설명을 사실에 맞게 고친다(0.3.7-demo부터 리허설이 아닌 세션에서는 학번이 들어가며 학생을 알아볼 수 있다).
8. 촬영 도구가 들어갈 때 쓰는 코드를 새 규칙에 맞는 가상 값(`3999`)으로 바꾼다.

### 빼는 것
서버 변경 전부(함수·표·허용 코드 범위·대화 가림 규칙), 필드 이름 `anonymousStudentCode`와 기록 계약, 개인별 QR 카드(`#c=`), 서버의 "오늘 수업" 표, 교사 화면 PIN 방식, 채점·기록 로직.

## 4. 지키는 것
- 채점·기록 로직(`src/domain`, `src/delivery`, `src/records`)은 바꾸지 않는다. 예외는 설명서 글(`researchBundle.ts`)뿐이다.
- 서버 코드(`supabase/`), 스냅샷 생성 스크립트, 생성물(`receiverCore.generated.js`)을 건드리지 않는다. 함수 배포가 필요 없어야 한다.
- 기록 없이 하기, 이어 하기(같은 코드·같은 세션), 캐릭터 저장(코드별)은 그대로 동작한다. 예전 코드(`A-01`)로 만든 캐릭터와 초안은 새 학번으로 이어지지 않는다(알고 둔다).
- 안내 없음 원칙: 주소·시작 화면이 다음 단계나 정답을 드러내지 않는다. 연구 세션이 정한 차시·도움 방식은 주소로도 바꿀 수 없다(`applySessionRules`).
- 주소에 학번·이름을 담지 않는다. QR은 기기 안에서 만들고 외부 서비스로 보내지 않는다.

## 5. 알고서 남기는 것
- 학번은 학교 안에서 누구인지 바로 아는 값이다. 기기 기록, 내려받는 CSV·연구 묶음, 서버의 AI 대화 기록에 그대로 남는다. 필드 이름은 계약 때문에 `anonymousStudentCode` 그대로다.
- IRB 원고(연구계획서·설명문·동의서)는 "프로그램에 이름·학번을 요구하지 않는다"고 적혀 있다. 연구 세션에 학번을 쓰려면 원고를 고쳐야 한다(집필 쪽 일).
- 학번으로 한 기록을 교사가 서버로 보내면 지금 서버는 거절한다("시험 세션·접수 기간이 아님").
- 학생이 AI 질문에 학번 숫자를 직접 쓰면 서버의 가림 규칙이 걸러 내지 못한다("2학년 2반 11번" 같은 글만 가린다).
- 주소 값은 학생이 손으로 고칠 수 있고, 교사 화면 PIN(0000)도 보안 장치가 아니다. "교사만 고른다"는 화면 구성으로 지키는 것이지 기술적으로 막는 것이 아니다.

## 6. 시험과 확인
- 시험(먼저 쓴다): 세션 종류별 코드 검사(학번 경계값, 가상 코드, 한글·빈 값), 수업 주소 만들기·읽기 왕복과 거절(알 수 없는 값·잠긴 세션·다른 판·길이), QR 표준 시험값과 길이 한도, 시작 화면에 고르기 입력이 없음(원본 글 검사), 교사 화면에 주소·QR 연결, 판 0.3.7-demo와 설명서 글. 기존 시험 가운데 `A-01`을 입장 코드 규칙으로 못 박은 것은 새 규칙으로 고친다(서버 쪽 시험은 그대로).
- 화면 확인(촬영 도구, 쓰기 요청 차단): 수업 주소로 열었을 때 시작 화면(학번 입력·오늘 과제 한 줄), 학번을 넣고 실습장 진입, 잘못된 주소의 안내, 리허설 세션의 가상 코드 안내. 콘솔 오류·예외·쓰기 요청 0.
- 교사 화면(PIN 뒤)의 주소·QR 모습은 MOON이 직접 본다(자동 확인에서 PIN을 넣지 않는다). QR 그림은 시험에서 판독해 주소가 그대로 나오는지 본다(판독 도구가 이 기계에 있을 때).

## 7. 구현 뒤 값
- 입장 코드(`src/app/session.ts`): 리허설 `^D-\d{2}$`(대문자로 바꿔 검사), 그 밖 `^[1-3][1-9](0[1-9]|[1-9]\d)$`(앞뒤 빈칸만 지움). 오류 글 — 학번: "학번은 학년·반·번호를 붙인 네 자리 숫자예요. 예: 2학년 2반 11번 → 2211", 가상 코드: "가상 코드는 D-01처럼 써요. 한글 자판이면 영문으로 바꿔 넣으세요."
- 시작 화면: 라벨 "학번 네 자리 (예: 2학년 2반 11번 → 2211)"(숫자 자판 `inputMode=numeric`, 최대 4자, 자리 표시 글 "네 자리 숫자"), 리허설은 "가상 코드 (예: D-01)"(자리 표시 "D-두 자리 번호"). 예시 값은 라벨에만 둔다(독립 검토 — 자리 표시가 미리 채운 값처럼 보였음). 안내 1번 "내 학번 네 자리를 넣고 시작해요."(리허설 "선생님이 알려 준 가상 코드를 넣고 시작해요."). "오늘 과제 {과제} · {차시} · {도움 방식}" 한 줄. 교사 설정이 없으면 시연 세션 · 첫 과제(제동력 사례 1) · 1~2차시 연습 · 안내 있음 · 진입 방향 없음.
- 수업 주소(`src/app/classLink.ts`): `#v=1&s=<세션>&t=<과제 사례>&p=<p|r|o>&m=<g|u>&d=<n|s|x>`. `v`는 주소 형식의 판(앱 판이 아님 — 앱을 다시 배포해도 같은 형식이면 예전 QR이 그대로 쓰인다. 형식을 바꿀 때 올린다). 예: `https://chassis-3d-lab.vercel.app/#v=1&s=DEMO-ONLY&t=case-rear-ok-240-200-600&p=p&m=g&d=x`(89자), 가장 긴 조합 `https://chassis-3d-lab.vercel.app/#v=1&s=DEMO-ONLY&t=case-rear-deviation-250-190-600&p=p&m=u&d=n`(96자). 고를 수 있는 세션 전 조합이 106자 안. 읽지 못한 주소는 `#` 값을 남긴다(새로고침해도 안내가 남음). 기기에 저장하지 못하면 이번 화면에서만 쓰고 `#` 값을 남긴다.
- 이어 하기 화면(독립 검토 뒤 더함): 끝내지 않은 수행이 있으면 앱이 시작 화면을 건너뛰므로, 수행 정보 줄에 차시를 더하고("코드 3999 · {과제} · {차시} · 안내 있음"), 이 기기의 교사 설정(수업 주소·교사 화면)이 초안과 세션·과제 사례·차시·도움 방식 가운데 하나라도 다르면 "오늘 과제(선생님이 정함) {과제} · {차시} · {도움 방식}"을 한 줄 더 보인다(시작 화면과 같은 계산 `src/app/todayTask.ts`). 같거나 설정이 없으면 보이지 않는다. 어느 버튼을 누르라고 권하지 않으며 버튼·동작은 그대로다. 주소를 읽지 못했으면 시작 화면과 같은 안내를 보인다. 주소를 읽을 때와 시작 화면·이어 하기가 같은 사례 목록(`knownCaseIds`, 빈 사례 ID 제외)을 쓴다.
- 잠금 정리: `TeacherPreset.locked` 없앰. 예전 저장값의 `locked`는 무엇이든 읽지 않는다. 저장할 때는 예전 판(0.3.6-demo까지)으로 되돌려도 읽히게 `locked: true`를 함께 적는다.
- QR(`src/teacher/qr.ts`): 계획 Task 2 코드 그대로(머리 주석과 `QR_MAX_BYTES = 106`만 더함). OpenCV 5.0.0 판독 왕복 — 표본 7개와 운영 주소 + 실제 설정 조합 12개(가장 긴 96자 포함) 모두 원문과 같음.
- 시험: 1,345 → 1,429개(138 → 143 파일) 모두 통과, 형 검사 통과. 주 번들 1,666,261 → 1,674,706 바이트(+8,445).
- 화면 확인(촬영 도구 사본, 쓰기 막기 유지): 주소 없음·수업 주소(1280×800, 820×1180)·새로고침·판이 다른 주소·잠긴 연구 세션 주소·리허설 주소·잘못된 학번(4101)·리허설에 학번(2211)을 넣은 경우, 그리고 학번 3999로 실습장 게임 화면 진입(`cams hero`). 콘솔 오류·예외·쓰기 요청 0건, 가로 넘침 없음. 독립 검토 뒤: 학번 3999로 과제를 수령해 초안을 만든 다음 다른 수업 주소(최소회전반경 · 5차시)로 다시 열어 이어 하기 화면의 오늘 과제 줄(1280×800, 820×1180), 같은 주소면 줄 없음, 읽지 못한 주소면 안내, 시작 화면의 새 자리 표시 글을 확인 — 콘솔 오류·예외·쓰기 요청 0건.
- 확인 스크립트: `scripts/check/flow-check.mjs`·`scripts/demo-video/demovid.mjs`도 수업 주소와 학번 3999(영상은 기록 없이 하기)로 들어가게 고쳤다. `puppeteer-core`가 설치돼 있지 않아 돌려 보지는 않았다(입력칸 이름·버튼 글을 소스로 대조).
