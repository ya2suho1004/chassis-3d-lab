# 수업 자료 모으기 설계 (1단계)

- 날짜: 2026-11-15
- 상태: MOON 승인(2026-11-16 "진행해")
- 앞 설계: `2026-11-14-student-number-and-class-link-design.md` (학번 입장과 수업 주소, 0.3.7-demo)
- 뒤 단계: 연구용 가명 처리(2단계)는 IRB 서류를 쓸 때 따로 설계한다.

## 1. 목적

실제 수업에서 학생이 마친 수행 기록을 서버에 모으고, 교사가 학생별 성취를 한 화면에서 본다.

지금은 세 가지가 막혀 있다.

1. 서버는 리허설용 가상 코드(`D-xx`)만 받는다. 학번으로 들어온 기록은 거절된다.
2. 기록은 교사가 그 태블릿의 교사 화면에서 전송을 눌러야 서버로 간다. 태블릿이 학생마다 한 대라 이 방식으로는 모을 수 없다.
3. 교사 화면에 학생별 성취를 보는 곳이 없다.

## 3. 범위

### 3-1. 수업용 세션

`src/data/session/sessions.json`에 종류 `class`를 더한다.

| 코드 | 이름 | 차시 구분 | 도움 방식 |
|---|---|---|---|
| `CLS-L12` | 수업 · 연습 | 1~2차시 연습 | 교사가 고름(안내 있음·없음) |
| `CLS-L5` | 수업 · 정리(안내 없음) | 5차시 정리 | 안내 없음 고정 |

- 학급 조건 코드는 둘 다 `CLS`.
- 입장은 학번 네 자리(지금 규칙 그대로).
- 기록의 `runPurpose`는 `demo`, `researchEligible`은 `false`로 둔다. 기록 형식(계약)을 바꾸지 않기 위해서다. 여기서 `demo`는 "연구용 접수가 아님"이라는 뜻으로 읽는다. 서버의 연구 기록 잠금은 그대로다.
- 세션을 둘로 나누는 까닭: AI 교관 설정이 세션마다 따로이고(연습·정리의 흐름이 다름), 리허설·연구 세션도 같은 짝으로 되어 있다.
- 학급은 학번 앞 두 자리로 가른다. 학급마다 세션을 만들지 않는다.
- 차시 이름(1~2차시, 5차시)은 지금 문구를 그대로 쓴다. 새 차시 계획이 확정되면 문구만 바꾼다.

### 3-2. 서버가 학번 기록을 받게 하기

- `scripts/build-demo-snapshots.mjs`: 세션 종류에 따라 허용 코드 형식을 정한다. `class` → `^[1-3][1-9](0[1-9]|[1-9][0-9])$`, 그 밖 → 지금처럼 `^D-[0-9]{2}$`.
- 스냅샷 원장은 덧붙이기만 한다. 기존 항목의 ID와 내용은 바뀌지 않는다. 새 항목은 36개(`CLS-L12` 24, `CLS-L5` 12).
- `npm run build:gs-snapshots`, `node scripts/build-receiver-core.mjs`로 수신 코드를 다시 만든다.
- 결과: 수업용 세션은 학번만 받고 `D-xx`는 거절한다. 시연·리허설 세션은 지금처럼 `D-xx`만 받는다. 공개 주소로 구경 온 사람이 시연 세션에 넣은 값은 서버에 가지 않는다.
- AI 교관용으로 `sessions` 표에 두 세션을 넣는 이관 파일을 새로 만든다(만들기만 하고 적용은 §6).

### 3-3. 마치면 자동으로 보내기

- 수업용 세션에서 수행을 마치거나 중단해 기록이 확정되면, 그 기록을 바로 서버로 보낸다.
- 보내는 대상은 수업용 세션의 기록뿐이다. 그 기기에 남은 시연·리허설 기록은 자동으로 보내지 않는다.
- "기록 없이 하기"는 지금처럼 저장도 전송도 하지 않는다.
- 못 보냈을 때(인터넷 끊김 등)는 기기에 남겨 두고 다시 시도한다(2026-11-16 검토 반영 — 한 명에 한 대라 교사가 태블릿마다 눌러 줄 수 없으므로 기록이 기기에 갇히지 않게):
  - 부르는 때: 앱을 열 때, 다음 수행을 마칠 때, 앱이 켜져 있는 동안 수업용 대기 기록 가운데 가장 이른 재시도 시각(타이머 하나, 앱이 닫히면 정리), 인터넷이 다시 연결될 때.
  - 인터넷이 끊겨 있으면(`navigator.onLine`이 false) 시도하지 않는다. 시도 횟수와 상태를 건드리지 않는다.
  - 인터넷이 다시 연결돼 부른 때에는 끊겨서 못 보낸(`NETWORK_ERROR`) 기록을 재시도 시각을 기다리지 않고 보낸다. 다른 사유는 재시도 시각을 지킨다.
  - 자동 전송에는 시도 상한이 없다. 실패해도 재시도 시각이 계속 잡힌다(기존 간격, 최대 10분). 교사 전송으로 상한(8회)에 닿아 재시도 시각이 빈 기록도 사유가 재시도할 수 있는 것이면 자동 전송이 다시 시도한다.
  - 다시 보내도 소용없는 사유(`CANONICAL_STORE_INVALID`, `RECEIPT_MISMATCH`, `ACCEPTED_AT_MISMATCH`)와 거절·충돌은 자동으로 다시 보내지 않는다(교사 전송 버튼으로만).
  - 자동 전송과 교사 전송은 한 줄로 서서 겹치지 않는다(같은 기록을 두 번 보내거나 늦은 실패가 접수 확인을 덮지 않게).
  - 교사 전송 버튼의 규칙(상한 8회, 강제 재전송)은 그대로다.
  - 타이머: 지난 재시도 시각이어도 기본 간격(30초)은 기다린다. 재시도 시각이 비었어도 자동으로 다시 보낼 기록(교사 전송으로 상한에 닿은 것)은 최대 간격(10분) 뒤로 건다. 교사 전송이 끝나면 보내지 않고 타이머만 다시 건다.
  - 한 차례에 결과 저장이 실패한 기록이 있었으면(기록이 지난 재시도 시각으로 남음) 다음 타이머를 최대 간격(10분)으로 건다. 실제 요청을 짧게 되풀이하지 않게 하려는 것이다.
- 교사 화면의 전송 버튼은 그대로 둔다(수동으로 다시 보내기).
- 결과 화면에 전송 상태를 한 줄로 보인다: "기록을 선생님께 보냈어요." / "아직 보내지 못했어요. 인터넷이 연결되면 다시 보내요." 정오나 판정은 넣지 않는다. 두 번째 문구는 자동으로 다시 보낼 기록에만 쓰고, 자동으로 다시 보내지 않는 기록(거절·충돌, 다시 보내도 소용없는 사유)과 서버 한도(`RATE_LIMITED`)는 "기록을 보내지 못했어요. 선생님께 알려 주세요."를 쓴다. `RATE_LIMITED`를 선생님께 알리게 하는 까닭: 서버 한도는 교사가 올려야 풀리고, 올린 뒤에는 자동 전송이 저절로 다시 보낸다.
- 결과 화면의 "보내는 중"은 이 기록이 들어간 차례가 끝날 때만 끈다. 앞 차례(다른 기록)가 도는 중에 확정하면 새 차례가 줄을 서는데, 앞 차례가 끝난 것만으로 "아직 보내지 못했어요"를 보이지 않게 한다.
- 시작 화면에 수업용 세션일 때 한 줄을 더한다: "마치면 수행 기록이 선생님께 보내져요."

함께 고치는 안전장치 두 가지:

1. 시연 세션에 학번으로 남은 기록은 교사가 전송을 눌러도 보내지 않고 건너뛴다(지금은 보내면 서버가 거절하고, 그 기록은 영영 다시 못 보낸다).
2. 수업용 세션 기록이 "세션 허용 안 됨"으로 거절되면, 교사의 전송 버튼으로 다시 보낼 수 있게 한다. 서버 배포보다 앱이 먼저 나가는 실수가 있어도 기록이 태블릿에 갇히지 않는다. 자동 재전송은 하지 않는다.

### 3-4. 교사 화면: 학생별 성취 표

- 위치: 교사 화면의 서버 관리(교사 로그인 뒤). 서버의 `records`를 읽는다. 읽기 권한은 지금 규칙 그대로(교사 계정만).
- 고르기: 세션(수업 · 연습 / 수업 · 정리), 학년, 반, 과제.
- 한 줄 = 학생 한 명 × 과제 하나. 학번 순으로 놓는다.
- 줄에 보이는 값은 그 학생이 그 과제에서 가장 최근에 끝낸 수행이다. 줄을 누르면 그 학생의 모든 수행이 날짜순으로 펼쳐진다.

| 칸 | 값 | 기록 필드 |
|---|---|---|
| 학번 | 2211 | `anonymousStudentCode` |
| 과제 | 제동력 사례 1 등 | `taskId`와 과제 판 |
| 완료 여부 | 완료 / 중단 | `completionStatus` |
| 검사 | 통과(n번째) / 통과 못함(n번 받음) / 검사 안 받음 | `npcInspectionResult`, `npcInspectionCount` |
| 오류 수 | 숫자 | `errorCount` |
| 걸린 시간 | 분:초 (멈춘 시간 제외) | `durationSeconds` |
| 수행 횟수 | 숫자 | 서버 기록 건수 |

알아 둘 점:

- 이 앱에서 "완료"는 교관 검사를 통과해야만 된다. 그래서 완료한 수행은 늘 검사 통과이고, 차이는 중단한 수행에서만 난다. 검사 칸에 몇 번째에 통과했는지를 함께 보여 두 칸이 서로 다른 정보를 갖게 한다.
- 표에는 마치거나 중단한 학생만 나온다. 하다가 태블릿을 덮은 학생은 서버에 기록이 없어 표에 없다. 명단을 넣지 않으므로 "안 한 학생"을 따로 세지는 못한다.
- 안전 위반, 처음 정답 수, 힌트, AI 질문 수는 표에 넣지 않는다. 기록에는 그대로 있으므로 나중에 칸을 더할 수 있다.

계산은 화면과 떼어 `src/teacher/achievement.ts`에 둔다(서버 기록 목록 → 표의 줄). 화면은 `src/screens/AchievementTable.tsx`.

## 4. 고칠 수 있는 곳 (승인 범위)

채점·기록 로직은 MOON이 범위를 열어 줄 때만 고친다. 이번 설계가 여는 범위는 아래뿐이다.

| 곳 | 고치는 내용 |
|---|---|
| `src/delivery/outbox.ts` | 보낼 기록을 거르는 조건(수업용만, 시연 세션의 학번 기록 건너뛰기), 자동 전송 모드의 재시도 규칙(끊김이면 시도 안 함, online 신호면 `NETWORK_ERROR`는 바로, 상한 없음, 다시 보내지 않는 사유), 전송함 처리 한 줄 세우기(2026-11-16 검토로 더함) |
| `src/delivery/submit.ts` | 다시 보낼 수 있는 거절 사유에 "수업용 세션의 세션 허용 안 됨" 추가(`rejectedClassSessionNotAllowed`). 2026-11-16 검토로 더함: 자동 전송용 `online` 칸(`SubmitDeps.online`), 자동으로 다시 보내지 않는 사유 목록(`NO_AUTO_RETRY_CODES`), 재시도 간격 상수 내보내기(`BACKOFF_BASE_MS`·`BACKOFF_MAX_MS`). 판정·전송 규칙은 그대로 |

## 5. 지켜야 할 규칙

- 안내 없음에서는 최초 응답이 모두 저장되기 전에 다음 단계나 정오를 드러내지 않는다. 전송 상태 문구에 판정을 넣지 않는다.
- 학번은 알아볼 수 있는 값이다. 주소(URL)에 넣지 않고, 서버에서는 교사 계정만 읽는다.
- 시험·확인에서는 실제 서버로 쓰지 않는다(가짜 서버·쓰기 차단). 실제 접수 확인은 MOON이 허락한 때에만 한다.
- 새 패키지를 설치하지 않는다.

## 6. 반영 순서 (각 단계는 MOON 허락 뒤)

1. 이관 파일 적용(`sessions` 표에 두 세션).
2. `submit` 함수 배포.
3. 서버 한도 값 바꾸기: 접수 기한(`SUBMIT_ACCEPT_UNTIL`, 지금 2026-12-01)과 새 기록 상한(`SUBMIT_MAX_NEW_ROWS`, 지금 서버 전체 200건).
   - 어림: 학생 수 × 과제 수 × 수행 횟수. 예) 4학급 100명이 과제 4개를 2번씩 하면 800건.
4. 앱 재배포.

순서가 바뀌어 앱이 먼저 나가면 수업용 기록이 거절된다. §3-3의 안전장치 2로 서버 배포 뒤 다시 보낼 수 있다.

Supabase 요금제(무료: 일주일 안 쓰면 멈춤, 자동 백업 없음)는 MOON이 정한다.

## 7. 알려진 한계

- 서버 접수 주소와 앱은 공개되어 있다. 공개 주소를 연 사람은 누구나 교사 화면(PIN은 보안 장치가 아님)에서 수업용 세션을 고르거나 수업 주소를 만들어, 아무 학번으로 수행을 마칠 수 있다. 그 기록은 서버로 가서 성취 표에 나오고 새 기록 건수 상한을 쓴다. 막는 장치는 접수 기한(`SUBMIT_ACCEPT_UNTIL`), 건수 상한(`SUBMIT_MAX_NEW_ROWS`), 교사가 성취 표의 접수 시각을 수업 시간과 맞춰 보는 것뿐이다. 코드로 더 막지는 않는다(더 막을지는 MOON이 정한다). 성적에 그대로 쓰려면 교사가 접수 시각을 확인해야 한다.
- 서버 기록은 고치거나 지울 수 없게 잠겨 있다(지우기는 철회 절차의 SQL로만). 교사가 수업용 세션에서 시험 삼아 넣은 학번 기록도 남는다. 시험은 리허설 세션으로 한다.
- 수업용 세션의 AI 교관 대화 기록에도 학번이 들어간다(지금 시연 세션도 같다).
- IRB 원고는 "학번을 묻지 않는다"고 쓰여 있다. 수업에서 모은 자료를 연구에 쓰는 방법(가명 처리, 동의 안 한 학생 빼기)은 2단계에서 서류와 함께 정한다.
- 한 태블릿을 여러 학생이 번갈아 쓰는 경우는 따로 다루지 않는다(MOON: 한 명에 한 대).

## 8. 확인 방법

- 시험: 스냅샷 수(지금보다 36개 많음: 원장 120→156, 서버 목록 121→157), 수업용 세션은 학번 수락·`D-xx` 거절, 시연·리허설은 학번 거절(가짜 서버로 `handleSubmit` 시험), 전송함 거르기, 자동 전송 시점과 재시도, 거절 기록 다시 보내기, 성취 표 계산(가장 최근 수행, 중단, 검사 횟수, 학년·반 거르기).
- `tsc`, 빌드, 전체 시험.
- 헤드리스 확인(쓰기 차단): 수업용 세션 입장 → 시작 화면 안내 문구 → 결과 화면 전송 상태 문구. 쓰기가 차단되므로 "보내지 못했어요" 쪽만 눈으로 본다.
- 성취 표 화면은 교사 로그인이 필요해 자동으로 열지 않는다. 가짜 자료를 넣은 미리보기 그림으로 모양만 확인하고, 실제 화면은 MOON이 본다.
- 독립 검토(새 검토자, 이 문서와 바뀐 범위만 줌).

- 결과 화면 문구: 보내는 중 "기록을 선생님께 보내는 중이에요.", 자동으로 다시 보내지 않는 기록(거절·충돌·다시 보내도 소용없는 사유)과 서버 한도(`RATE_LIMITED`)는 "기록을 보내지 못했어요. 선생님께 알려 주세요." 이 기기 저장에 실패했으면 줄을 보이지 않는다(저장 실패 안내가 따로 있음).
- 시작 화면 안내와 결과 화면 상태 줄은 전송 주소가 있는 빌드에서만 보인다(주소가 없으면 보내지 않으므로).
