# 도감 창 설계

- 날짜: 2026-11-16
- 상태: MOON 지시("도감 펼쳐 보는 창 설계해서 진행해", 2026-11-16). 아래 §2의 두 가지는 MOON이 답하지 않아 지휘 세션이 기본값을 골랐다. 바꾸기 쉽다.

## 1. 목적

실습장에서 장비를 누르면 도감 숫자("도감 3/23")가 오르지만, 모은 장비를 한꺼번에 보는 곳이 없다. 숫자를 누르면 모은 장비가 펼쳐지는 창을 만든다.

## 2. 고른 기본값

| 정할 것 | 고른 값 | 까닭 |
|---|---|---|
| 저장 | 학번별로 이 기기에 남긴다(캐릭터 저장과 같은 방식). 서버·수행 기록에는 넣지 않는다. "기록 없이 하기"는 남기지 않는다. | 한 명이 한 대를 여러 차시에 쓴다. 들어올 때마다 0부터면 도감이 차지 않는다. |
| 과제 중 열람 | 과제를 받은 뒤에도 열 수 있다. 가까이 보기·연습·기록 창이 열린 동안에는 열 수 없다. | 창에는 이미 누른 장비의 설명 카드와 같은 글만 나온다. 장비를 다시 누르면 볼 수 있는 내용이라 새 단서가 아니다. |

## 3. 범위

### 3-1. 여는 곳
- 게임 화면: 이름표 옆 "도감 n/23"을 버튼으로 바꾼다. 누르면 도감 창이 열린다.
- 기본 화면(패널): 위쪽 줄의 "도감 n/23" 옆에 "도감 보기" 버튼.
- 가까이 보기·연습·기록 창이 열린 동안에는 버튼을 누를 수 없다(지금의 "장면이 조용한 때" 규칙과 같다).

### 3-2. 창
- 화면 위에 뜨는 창이다. 닫기 버튼, Esc, 바깥 누르기로 닫는다. 열려 있는 동안 뒤의 장면은 누름에 반응하지 않는다. 닫으면 초점이 도감 버튼으로 돌아간다.
- 머리: "도감 n/23".
- 본문: 장비 카드 23장. 순서는 배치 자료(`layout.equipment`) 순서로 고정한다(모은 것과 아닌 것이 섞여도 자리가 바뀌지 않는다).
  - 모은 장비: 종류 그림(아이콘), 이름, 설명. 설명은 장비 카드에 나오는 글(`info`)을 그대로 쓴다.
  - 아직 못 본 장비: 이름과 설명을 가린다("?"와 "아직 못 본 장비").
- 카드에는 과제와 관련된 표시를 넣지 않는다(작동 장비 표시, 단계 순서, 다음 장비, 정오 없음). 모으기 순서로 정렬하지도 않는다.
- 태블릿(820폭)과 폰 폭에서 가로 넘침 없이 세로로 밀어 본다.
- 창을 열고 닫는 것은 수행 기록에 사건으로 남기지 않는다. 장면 누름 효과·소리 사건도 내지 않는다. 버튼 누름 느낌(`data-feel="press"`)만 쓴다.

### 3-3. 저장
- 새 모듈 `src/app/codexStore.ts`: 학번(입장 코드)별로 모은 장비 번호 목록을 이 기기(localStorage)에 둔다. 캐릭터 저장(`saveAvatar`·`loadAvatar`)의 방식을 따른다.
- 실습장에 들어올 때 그 코드의 목록으로 도감을 채운다. 배치 자료에 없는 번호는 버린다.
- 장비를 처음 누르면 목록에 더하고 저장한다. "도감에 등록" 꼬리표와 숫자 튐은 지금처럼 새로 등록한 때만.
- "기록 없이 하기"는 읽지도 쓰지도 않는다(지금처럼 그 수행 동안만).
- 저장을 못 해도(저장 공간 막힘) 실습은 그대로 된다.

### 3-4. 문서·판
- 앱 판 `0.4.1-demo`(겉모습이 바뀜).
- `docs/design/docs/20_2026-10-28_면담결정_변경기록.md`에 D49, `02_GAME_FLOW_AND_STORYBOARD.md`·`README.md`에 한 줄.
- 이 문서 끝에 "구현 결과"를 덧붙인다.

## 4. 넣지 않는 것
- 장비 사진·3D 그림(썸네일). 지금 자료에는 화면에 쓸 그림이 없다. 필요하면 다음에.
- 카드에서 "그 장비로 가기".
- 도감을 다 모았을 때의 보상.
- 설명 글 다듬기. 지금 설명에는 개발용 메모(실측·가정 표시 등)가 섞여 있다. 이번에는 그대로 쓰고, 고치는 일은 따로 한다.

## 5. 지켜야 할 규칙
- 채점·기록 로직(`src/domain`, `src/delivery`, `src/records`)을 고치지 않는다. 도감은 수행 기록·서버에 들어가지 않는다.
- 안내 없음에서 최초 응답이 모두 저장되기 전에 다음 단계·정오를 드러내지 않는다. 창에 과제 진행과 관련된 것을 넣지 않는다.
- 학번은 알아볼 수 있는 값이다. 주소·콘솔에 넣지 않는다. 기기 저장은 캐릭터 저장과 같은 수준으로만.
- 새 패키지를 설치하지 않는다. 특정 게임의 화면을 따라 만들지 않는다.

## 6. 확인 방법
- 시험: 저장 모듈(읽기·쓰기·모르는 번호 버리기·저장 실패), 카드 목록 계산(순서 고정, 가림), 배선(버튼, 조용한 때 막힘, 기록 없이 하기는 저장 안 함, 사건 없음).
- `tsc`, 빌드, 전체 시험.
- 헤드리스 확인(쓰기 차단): 게임 화면에서 장비 몇 개를 누르고 창을 열어 1280×800·820×1180 그림, 새로고침 뒤 다시 들어와 숫자가 남는지, 안내 없음 과제 중에 열었을 때 과제 관련 표시가 없는지.
- 독립 검토(새 검토자).

| §3-2 창 | `src/screens/CodexWindow.tsx`. 기록 창처럼 div와 `role="dialog"`·`aria-modal`·`aria-labelledby="codex-title"`. 열 때 초점은 제목, Tab은 창 안에서 돈다, ✕·Esc(한글 조합 중 제외)·어두운 바탕 누르기로 닫고 초점은 연 버튼(모르면 도감 버튼)으로. 카드 줄은 `src/app/codexList.ts`(배치 순서 고정, 못 본 장비는 번호 말고 아무것도 싣지 않아 이름·설명·종류가 DOM에 없다). 종류 그림은 `Icon`에 직접 그린 선 아이콘 9개를 더했다(도감 책, 롤러·조작부·책상·차량·토 게이지·리프트·스탠드·작업대). 창 아래 저장 방식 한 줄. 창이 열린 동안 캐릭터는 키보드로도 걷지 않는다(`holdStill={recording \|\| codexOpen}`). |
| §3-2 사건 없음 | 창은 `fire`·소리·기록을 부르지 않는다. 여는 버튼은 상태 줄의 누름 느낌 구역 안, 닫기 버튼에 `data-feel="press"`. 바탕 누르기·Esc는 소리도 없다. |
| §3-2 겉모습 | 크림 바탕·갈색 선·둥근 모서리 카드, 머리는 갈색 띠(의뢰 카드 제목과 같은 색). 화면에 고정된 바탕(`z-index:10`, 작업 목록·질문 창·교관 대화 위). 카드 칸 `minmax(min(220px, 100%), 1fr)`·긴 낱말 끊기로 가로 넘침 없음. 닫기 44px. 뜨는 움직임은 움직임 줄이기에서 없다. 겹침 측정 제외 목록에 `.g-codexbtn::after`·`.codex-wrap`을 이유와 함께 더했다. |
| §3-3 저장 | `src/app/codexStore.ts` — 열쇠 `chassis.codex.v1`, 코드 → 번호 목록. `loadCodex(code, 배치 번호)`는 배치에 없는 번호·겹친 번호를 버리고, `addToCodex(code, id)`는 처음 누를 때 더한다. 둘 다 저장 공간이 막혀도 던지지 않는다. 실습 화면은 기록 없이 하기면 부르지 않는다. 이미 저장된 장비는 처음부터 도감에 있어 다시 눌러도 꼬리표·숫자 튐이 없다. |
