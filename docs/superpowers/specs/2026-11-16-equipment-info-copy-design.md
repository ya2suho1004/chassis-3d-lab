# 장비 설명 글 정리 — 설계 (2026-11-16)

MOON 승인: 2026-11-16("추천대로 진행"). 문장 초안과 정할 것 목록은 `docs/copy/2026-11-16_장비설명_초안.md`.

## 문제
배치 자료 `src/data/layout/layout.dev-provisional.json`의 `equipment[].info`가 장비 카드(`LabScreen.tsx`)와 도감 창(`CodexWindow.tsx`, `codexList.ts`)에 그대로 나온다. 그 안에 실측·가정·날짜·지시 같은 개발 메모가 섞여 학생에게 보였다. 게임 화면 장비 카드에는 "[부분 실측]" 같은 근거 꼬리표도 보였다.

## 결정
1. **`info`는 학생용 문장만 담는다.** 떼어 낸 메모는 같은 장비의 기존 `note` 칸 끝에 ` / 설명 글에서 옮김(2026-11-16): …`으로 덧붙인다. 앱은 장비의 `note`를 읽지 않으므로 새 필드도, 읽는 코드 수정도 없다.
   - 버린 안: 학생용 필드를 새로 둠(설명이 두 군데에 생기고 읽는 코드·시험을 함께 고쳐야 함), `devNote`를 새로 둠(기존 `note`와 겹침).
2. **문장**: 23개 중 9개는 메모만 뗌, 2개(시험 차량, 리프트 3)는 글 전부가 메모라 새로 씀, 12개는 그대로.
3. **규정값·공식·절차 문장은 모두 그대로 둔다**(MOON 결정). 목록:
   - 최소회전반경 측정 차량: "R = L ÷ sin α + r", "과제에서 앞바퀴가 돌고 측정판 눈금으로 조향각을 읽는다"
   - 공용 조작부: 버튼 이름 일곱 개, "사용 후 플러그를 뺀다"
   - 엔드플레이·캠버 캐스터·톤휠 간극·디스크의 규정값(지금 앱에 이 장비들의 과제는 없다)
   - 이 장비들로 과제를 새로 만들 때는 안내 없음 규칙(최초 응답이 모두 저장되기 전에 답·다음 단계를 드러내지 않음)에 비추어 이 문장들을 다시 본다.
4. **근거 꼬리표**: 게임 화면 장비 카드(`.g-info`)에서만 없앤다. 기본 화면(패널) 카드와 교사용 눈검토·실측 입력 화면은 그대로 둔다.

채점·기록 로직(`src/domain`, `src/delivery`, `src/records`), 배치 좌표·치수·`basis`, 기록 형식.
